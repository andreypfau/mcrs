You do not need to learn all of Rust to write a plugin. This page lists what the tutorials use. The Java snippets here are illustrations, they are not from mcrs. The Rust snippets are small sketches too, not compiled in CI.

## What you need

| Rust | Java idea |
|---|---|
| `struct`, `enum` | `class` with fields, `enum` that can carry data |
| `impl` block | Methods of a class |
| `trait` | `interface` |
| `Option<T>` | A value that may be `null` |
| `Result<T, E>` and `?` | Checked exceptions |
| `match` | `switch` that must cover every case |
| Closure `\|x\| ...` | Lambda |
| `Vec`, `HashMap`, `String` and `&str` | `List`, `Map`, `String` |
| `#[derive(Clone)]` | Generated copy and equals code |
| `&T` and `&mut T` | Many readers or one writer, checked at compile time |
| Modules, `use`, `Cargo.toml` | Packages, imports, `build.gradle` |

## Ownership in one paragraph

A value has one owner. You can lend it as `&T` (many readers) or `&mut T` (one writer), never both at once. In Bevy systems this is written in the parameters: `Query<&T>` reads, `Query<&mut T>` writes. You rarely write lifetimes. The habits to change: store an `Entity` id instead of a reference to a player, and call `.clone()` instead of sharing. Do not copy patterns from Rust servers built on `Arc<Mutex<..>>`, the project avoids them in its library layers, see <Status issue={566} state="wip" />. More on ownership: [the Rust Book chapter](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html).

## Three errors you will meet

1. Use of a moved value. You passed a value by value and used it again. Pass `&value` or call `.clone()`.
2. A function is not accepted as a system. One parameter has a type Bevy cannot supply. Check that every parameter is `Res`, `ResMut`, `Query`, `Commands`, a message reader or writer, or `Local`.
3. Two parameters of one system want the same data, one of them as `&mut`. The scheduler reports it when it builds the graph, at startup, not at compile time. Merge the queries or split the system.

## What you do not need yet

Lifetimes (except reading the signatures of other people), `unsafe`, procedural macros and `async`.

## Where to read

- [The Rust Programming Language](https://doc.rust-lang.org/book/): read ownership, enums and `match`, error handling and traits.
- [Rust by Example](https://doc.rust-lang.org/rust-by-example/): short runnable examples.
- [Rustlings](https://github.com/rust-lang/rustlings): small exercises.
- [Cargo guide](https://doc.rust-lang.org/cargo/guide/): `Cargo.toml` and dependencies.
- [Bevy learn](https://bevy.org/learn/) and the [ECS examples](https://github.com/bevyengine/bevy/tree/main/examples/ecs).
- [Unofficial Bevy Cheat Book](https://bevy-cheatbook.github.io/): it can lag behind. mcrs uses Bevy 0.19, where `Message`, `MessageReader` and `On<E>` are the names, older text may use other names.
- [bevy_ecs on docs.rs](https://docs.rs/bevy_ecs/0.19.1/bevy_ecs/) for exact signatures.
