You do not need to learn all of Rust to write a plugin. This page shows the part that the tutorials use, next to the Java you already know, and ends with links for when you want more. The Java snippets are illustrations and are not part of mcrs. The Rust snippets are short sketches too, and CI does not compile them.

## The Rust you need, in Java terms

| Rust | Java idea |
|---|---|
| `struct`, `enum` | `class` with fields, `enum` that can carry data |
| `impl` block | Methods of a class |
| `trait` | `interface` |
| `Option<T>` | A value that may be `null` |
| `Result<T, E>` and `?` | Checked exceptions |
| `match` | `switch` that must cover every case |
| Closure `\|x\| ...` | Lambda |
| `Vec`, `HashMap`, `String` and `&str` | `List`, `Map`, `String` |
| `#[derive(Clone)]` | Generated copy and equals code |
| `&T` and `&mut T` | Many readers or one writer, checked at compile time |
| Modules, `use`, `Cargo.toml` | Packages, imports, `build.gradle` |

You can leave `unsafe`, procedural macros and `async` for later. The same goes for lifetimes, except that you will meet them when you read signatures that other people wrote.

## The same code in Java and in Rust

A Java class becomes two things in Rust: a `struct` for the data and an `impl` block for the methods.

<Tabs syncKey="jvm">
<TabItem label="Java">
```java
// a class with data and a method
class Counter {
    private int ticks;
    void tick() { ticks++; }
}
```
</TabItem>
<TabItem label="Rust">
```rust
// a struct with data, and an impl block with a method
struct Counter {
    ticks: u32,
}

impl Counter {
    fn tick(&mut self) {
        self.ticks += 1;
    }
}
```
</TabItem>
</Tabs>

A Paper plugin extends `JavaPlugin`, and an mcrs plugin implements the `Plugin` trait. The `#[derive(Clone)]` line is there because every dimension gets its own copy of the plugin.

<Tabs syncKey="jvm">
<TabItem label="Java">
```java
// a plugin is an interface implementation
public class MyPlugin extends JavaPlugin {
    @Override
    public void onEnable() { /* register things */ }
}
```
</TabItem>
<TabItem label="Rust">
```rust
// a plugin is a trait implementation; it must be Clone for dimensions
#[derive(Clone)]
struct MyPlugin;

impl Plugin for MyPlugin {
    fn build(&self, app: &mut App) {
        // register systems, resources, observers
    }
}
```
</TabItem>
</Tabs>

Where Java returns `null` or throws an exception, Rust returns an `Option` or a `Result`, so both cases are visible in the type. The `?` operator returns the error to the caller.

<Tabs syncKey="jvm">
<TabItem label="Java">
```java
// null for "no value", exceptions for errors
Player p = lookup(name);
if (p == null) return;
int n = Integer.parseInt(text); // may throw
```
</TabItem>
<TabItem label="Rust">
```rust
// Option and Result make both cases visible in the type
let Some(p) = lookup(name) else { return };
let n: i32 = text.parse()?; // returns the error to the caller
```
</TabItem>
</Tabs>

A closure does the job of a lambda. In the Rust tab the closure is an observer, which is a function that runs when an event is triggered.

<Tabs syncKey="jvm">
<TabItem label="Java">
```java
// a lambda as a handler
events.on(ChatEvent.class, e -> e.setCancelled(true));
```
</TabItem>
<TabItem label="Rust">
```rust
// a closure as a handler (an observer)
app.add_observer(|mut e: On<PlayerChatEvent>| {
    e.cancelled = true;
});
```
</TabItem>
</Tabs>

## A value has one owner

A value in Rust has one owner. The owner can lend it as `&T` to many readers or as `&mut T` to one writer, but never both at once. In a Bevy system you write this in the parameters, where `Query<&T>` reads and `Query<&mut T>` writes. You rarely write lifetimes.

Two habits change because of this. Keep an `Entity` id where you would keep a reference to a player, and call `.clone()` where you would share a value. Do not copy patterns from Rust servers built on `Arc<Mutex<..>>`, because the project avoids them in its library layers (<Status issue={566} />). The [ownership chapter of the Rust Book](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html) explains the rules in full.

## Three errors you will meet

| Error | Cause | Fix |
|---|---|---|
| Use of a moved value | You passed a value by value and then used it again | Pass `&value` or call `.clone()` |
| A function is not accepted as a system | One parameter has a type that Bevy cannot supply | Check that every parameter is `Res`, `ResMut`, `Query`, `Commands`, a message reader or writer, or `Local` |
| Two parameters of one system want the same data, one of them as `&mut` | The scheduler reports this when it builds the graph at startup, and the compiler does not catch it | Merge the queries or split the system |

## Where to read more

- In [The Rust Programming Language](https://doc.rust-lang.org/book/), read the chapters on ownership, enums and `match`, error handling and traits.
- [Rust by Example](https://doc.rust-lang.org/rust-by-example/) has short runnable examples.
- [Rustlings](https://github.com/rust-lang/rustlings) is a set of small exercises.
- The [Cargo guide](https://doc.rust-lang.org/cargo/guide/) covers `Cargo.toml` and dependencies.
- [Bevy learn](https://bevy.org/learn/) and the [ECS examples](https://github.com/bevyengine/bevy/tree/main/examples/ecs) introduce Bevy.
- The [Unofficial Bevy Cheat Book](https://bevy-cheatbook.github.io/) can lag behind. mcrs uses Bevy 0.19, where the names are `Message`, `MessageReader` and `On<E>`, and older text may use other names.
- [bevy_ecs on docs.rs](https://docs.rs/bevy_ecs/0.19.1/bevy_ecs/) has the exact signatures.
