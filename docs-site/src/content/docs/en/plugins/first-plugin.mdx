You will add a plugin that counts server ticks. The plugin lives in your own copy of the mcrs repository, next to the server binary. mcrs has no plugin loader and no jar files (see [This is not the Paper API](/docs/en/plugins/not-paper/)), so "installing a plugin" means adding Rust code to the program that starts the server.

<Aside type="caution" title="WIP">
The way to build a plugin in its own project, with mcrs as a git dependency, is not checked. The crates are not published (<Status issue={321} state="undecided" />) and the examples workspace does not exist yet (<Status issue={288} state="wip" />). This page edits `src/main.rs` inside the clone instead. The code comes from test files of the repository. We did not run these steps outside the repository tests.
</Aside>

## Words you will see now

If Rust and Bevy are new to you, read these eight lines first. The full minimum is on [Rust for Java developers](/docs/en/plugins/rust-for-java/).

| Word | Closest Java idea | Meaning here |
|---|---|---|
| plugin | `JavaPlugin` with `onEnable` | a struct with a `build` method that adds systems and resources to an app |
| system | a scheduled task or an event handler | a function that Bevy runs on a schedule, such as `FixedUpdate` |
| resource | a singleton field of the server | one value per world, read with `Res<T>` or `ResMut<T>` |
| observer | an event listener | a function that runs when an event is triggered, written with `On<Event>` |
| query | a stream over all players, with a filter | a system parameter that visits entities with the components you name |
| `&mut` | a mutable reference | a borrow that may change the value; one at a time |
| `Clone` | `clone()` | a copy of the value; a dimension plugin needs it, see below |
| dimension world | one `World` object per dimension | each dimension has its own world, and your plugin is built once in each |

## What you build

A resource `Ticks` holds a number. One system adds one to it each server tick. The test file of the repository has exactly this plugin, and it counts in the overworld and in the nether.

## Step 2: the plugin

A plugin is a struct that implements `Plugin`. This one registers a resource and a system. The system runs in `FixedUpdate` and adds one to the counter. The test uses a const generic `ALL` to run two variants. Read it as a plain `CountTicks` and ignore `ALL`.

<Example file="crates/mcrs_minecraft_server/tests/it/dimension_plugins.rs" from={"#[derive(Resource, Default)]\nstruct Ticks<const ALL: bool>(u32);"} to={"    }\n}"} title="A plugin that counts ticks" />

Your plugin must be `Clone`. The server builds one copy of it for every dimension world, so it needs to copy it. The binary already has a small plugin that shows the shape:

<Example file="src/main.rs" from={"#[derive(Clone)]\nstruct LogInsteadOfPanicPlugin"} to={"    }\n}"} title="The smallest Clone plugin in src/main.rs" />

## Step 3: register it with add_dimension_plugin

In `serve()` of `src/main.rs`, the server already registers one plugin the right way. Add yours on the next line.

<Example file="src/main.rs" from="fn serve() -> AppExit" to="app.add_dimension_plugin(LogInsteadOfPanicPlugin);" title="Where serve() registers a dimension plugin" />

<Aside type="caution" title="The trap: add_plugins is not enough">
Each dimension runs as a separate Bevy `SubApp` with its own `World`. A plugin that you add with `app.add_plugins(...)` goes to the main app. It never reaches the simulation of a dimension (<Status issue={280} state="works" />). Your system would build without an error and never see a block, a mob or a player entity. Use `add_dimension_plugin(plugin)` for every dimension, or `add_dimension_plugin_to(key, plugin)` for one. The plugin goes in before the dimensions spawn, so call it before the server starts. More in [Dimensions](/docs/en/plugins/dimensions/).
</Aside>

## Step 4: see the count

The test plugin does not print anything. It asserts that the counter is above zero in both worlds (`ticks::<true>(...)` in the same file). The command below runs this test. It is the pattern that the chat test also uses (<Status pr={636} state="works" />).

```bash
cargo test -p mcrs_minecraft_server --test it dimension_plugins::
```

We did not run this command for this page. The repository has no log line for this plugin, so this page shows no expected log. If you want one, add a `tracing::info!` call in your system.

## The same in Paper

<Tabs syncKey="jvm">
<TabItem label="Paper (for comparison)">
This is illustrative Java. It is not from the repository and it is not mcrs code.

```java
public final class CountTicks extends JavaPlugin {
    private long ticks;

    @Override
    public void onEnable() {
        getServer().getScheduler().runTaskTimer(this, () -> ticks++, 0L, 1L);
    }
}
```
</TabItem>
<TabItem label="mcrs">
Same idea, with three differences. The plugin is part of the server program, not a jar. The counter is a resource in a world, not a field of your class. The task is a system that Bevy schedules, and it runs once in each dimension world.
</TabItem>
</Tabs>
