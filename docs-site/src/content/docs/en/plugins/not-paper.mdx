A plugin written for Paper does not run on mcrs. This page is for developers who come from Paper or Bukkit. It tells you what you do in place of writing against a plugin API, what already works and what is still missing.

mcrs has no Bukkit-like API and no facade crate, and that is a decision of the project.[^437] It also has no plugin loader today, so the server cannot load a jar, a wasm module or a script, and JVM code in Java or Kotlin cannot run inside it. Nobody has opened an issue about a loader or made a decision on one, so this page does not say "never".

What you do today is write a Bevy plugin in Rust, add it next to the server plugins in your own `main`, and build one binary. This is closer to [Minestom](https://minestom.net/), where the server is a library and you write the `main`, than to Paper, where you get a ready server and put jars into `plugins/`. The direction of the project is mcrs as a library, from a proxy to a full server.[^180]

<Aside type="caution" title="Early WIP">
The public library API is not stable. mcrs targets one game version at a time (<code dir="auto">{fact('snapshot')}</code>) and keeps no backward compatibility.[^412]
</Aside>

## What works today

The table lists what your code can already do, with the issue or the pull request behind each row.

| Need | State | Where |
|---|---|---|
| Remove or replace a part of the server | The server is a group of plugins, and you can disable its members | <Status issue={279} /> |
| Add your code to every dimension or to one | `add_dimension_plugin` and `add_dimension_plugin_to` | <Status issue={280} /> |
| Vanilla gameplay as removable plugins | Done | <Status issue={282} /> |
| Intercept and cancel a chat line | `PlayerChatEvent`, the only public cancellable event | <Status pr={636} state="works" /> |
| Register your own command | `add_command` with a typed command tree | <Status pr={579} state="works" /> |

The entry point is [src/main.rs](https://github.com/andreypfau/mcrs/blob/main/src/main.rs). It creates the app and adds `MinecraftServerPlugins`, [the plugin group](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server/src/lib.rs) of the server.

## What is not there yet

Each row below has an issue, except the plugin loader.

| Need | State |
|---|---|
| Public cancellable events for join, leave, block break, block place and movement | <Status issue={283} /> |
| Replace the chunk source (a flat or empty world, your own generator) | <Status issue={281} /> |
| Create and remove dimensions while the server runs | <Status issue={546} /> |
| Depend on published crates (today only a git dependency) | <Status issue={321} /> |
| Plugin loader for jars, wasm or scripts | <Status state="undecided" /> no issue, no decision |
| Save the world to disk | <Status issue={78} /> |

## Paper habits that do not carry over

| Paper habit | In mcrs |
|---|---|
| `plugin.yml`, jar in `plugins/` | No. Your code is compiled into the server binary |
| Static `Bukkit.getServer()` | No, rejected in <Status issue={437} />. A system receives its data as parameters |
| A stable API with versions | No. You build against the public crates and plugins, and their versions are not stable |
| `/reload` and hot reload of code | No. Data pack reload is planned in <Status issue={316} /> |
| Scripting (Lua, JS) | No issue, no decision |
