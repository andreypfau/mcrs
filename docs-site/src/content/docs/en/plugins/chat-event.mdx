This tutorial shows how a plugin cancels a chat line or replaces its text. Chat is the first public player event of mcrs and, for now, the only one. It is the first merged part of the planned public, cancellable player events, and events for join, leave, movement and blocks do not exist yet.[^283][^pr636] The examples come from test files of the repository, and we did not run them outside those tests.

## The event has three fields

The server raises `PlayerChatEvent` for a chat line before it broadcasts the line.

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" from={"#[derive(Event, Debug)]\npub struct PlayerChatEvent"} title="PlayerChatEvent" />

| Field | Meaning |
|---|---|
| `player` | the entity of the sender, in the world of the sender's dimension |
| `text` | the line as a `Text`, not a `String`; change it to rewrite the line |
| `cancelled` | set it to `true` and the line is not broadcast |

`Text` is the styled text type of the protocol, so a line can carry colors and components. To make a `Text` from a string, use `into_text()`, as the tests do.

## Which lines raise the event

The server checks a line first and raises the event only when the line passes, so the event comes after the checks and before the broadcast.

| Line | What the server does |
|---|---|
| Has an illegal character | Raises no event and logs that it dropped the line |
| Comes from a player who hides chat | Raises no event and sends the player the "chat disabled" message |
| Any other line | Raises the event in the dimension world of the sender. After the observers ran, it reads `cancelled` and `text` and broadcasts |

The trigger runs in a queued command. Because of that, the broadcast happens right after `handle_chat` ends and not inside it.

## Put the observer in a dimension plugin

Chat runs inside each dimension world, so the observer has to be in the dimension world as well. The tests add it to the world directly with `server.world().add_observer(...)`. In a real server, put `app.add_observer(...)` into the `build` method of a `Clone` plugin and register the plugin with `add_dimension_plugin`. `ChatPlugin` itself does the same for its own observer:

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" from="impl Plugin for ChatPlugin" title="ChatPlugin adds its observer in build" />

<Aside type="caution" title="WIP: open questions from PR 636">
The pull request that added the event leaves three points open.[^pr636] The first is where the event should live, because it is in `mcrs_minecraft_chat_server` while the plan for player events says "raised by the engine".[^283] The second is observer order. Bevy has no priority for observers, so two plugins that rewrite one line give a result that depends on the order. The third is the length of replaced text, because the 256-character limit is on the packet and a plugin can set a longer text.
</Aside>
