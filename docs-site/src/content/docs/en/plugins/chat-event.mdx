Chat is the first and, for now, the only public player event of mcrs. It is the part of <Status issue={283} state="partial" /> that <Status pr={636} state="works" /> merged. Join, leave, movement and block events do not exist yet. Examples here come from test files of the repository, and we did not run them outside those tests.

## The event

The server raises `PlayerChatEvent` for a chat line, before it broadcasts the line. The event has three fields.

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" lines="19-24" title="PlayerChatEvent" />

| Field | Meaning |
|---|---|
| `player` | the entity of the sender, in the world of the sender's dimension |
| `text` | the line as a `Text`, not a `String`; change it to rewrite the line |
| `cancelled` | set it to `true` and the line is not broadcast |

`Text` is the styled text type of the protocol, so a line can carry colors and components. To make one from a string, use `into_text()`, as the tests do.

## When it fires

The event comes after the checks of the server and before the broadcast.

- A line with an illegal character raises no event, and the server logs that it dropped the line.
- A line from a player who hides chat raises no event, and the player gets the "chat disabled" message.
- Any other line raises the event in the dimension world of the sender. After the observers ran, the server reads `cancelled` and `text` and broadcasts.

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" lines="64-93" title="Raise the event, then broadcast" />

The broadcast happens right after `handle_chat` ends, not inside it, because the trigger runs in a queued command.

## Where the observer lives

Chat runs inside each dimension world, so the observer has to be in the dimension world as well. The test adds it to the world directly (`server.world().add_observer(...)`). In a real server, put `app.add_observer(...)` into the `build` method of a `Clone` plugin and register it with `add_dimension_plugin`. `ChatPlugin` itself does the same for its own observer:

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" lines="26-33" title="ChatPlugin adds its observer in build" />

See [Your first plugin](/docs/en/plugins/first-plugin/) for why `add_plugins` does not work here.

<Aside type="caution" title="WIP: open questions from PR 636">
Three points are open in the PR text. First, where the event should live: it is in `mcrs_minecraft_chat_server`, while the issue says "raised by the engine". Second, observer order: Bevy has no priority for observers, so two plugins that rewrite one line give a result that depends on the order. Third, the length of replaced text: the 256-character limit is on the packet, and a plugin can set a longer text. Track them in <Status issue={283} state="partial" /> and <Status pr={636} state="works" />.
</Aside>
