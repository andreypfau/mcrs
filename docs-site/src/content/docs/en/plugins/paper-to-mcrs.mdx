This page is a lookup table for people who know Paper, Velocity or Minestom. Find the name you know, and the row shows the nearest thing in mcrs and its state today. If "entity" and "system" are new words, read [From objects to data](/docs/en/plugins/mental-model/) first.

<Aside type="caution" title="Every row is an analogy">
No row is a drop-in replacement, because mcrs has no Bukkit-like API, as [This is not the Paper API](/docs/en/plugins/not-paper/) explains. A row marked wip is a planned feature that has an issue and no code yet. A row marked undecided has no issue and no decision.
</Aside>

## Life cycle

| JVM | mcrs | State | Notes |
|---|---|---|---|
| `JavaPlugin`, `onEnable` | `impl Plugin for X` with `fn build(&self, app: &mut App)` | <Status issue={279} /> | As in Minestom, you write your own `main`, see [src/main.rs](https://github.com/andreypfau/mcrs/blob/main/src/main.rs). There is no `plugin.yml` and no separate jar |
| `onDisable` | No hook. Shutdown goes through a `ShutdownRequest` message | <Status state="partial" doc="crates/mcrs_minecraft_engine_server/src/shutdown.rs" /> | The embedder writes the request, or calls `request_shutdown` on a `ServerThread`. The plugin installs no signal handler |
| `depend:` and `softdepend:` | A plugin group: a member that needs another fails in `build` and names the missing one | <Status issue={279} /> | See `MinecraftServerPlugins` in [lib.rs](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server/src/lib.rs) |
| Disabling a bundled feature | `server.disable::<SomePlugin>()` on the plugin group | <Status issue={282} /> | Used in [`main.rs`](https://github.com/andreypfau/mcrs/blob/main/src/main.rs) to switch the mob brain off |
| `/reload`, PlugMan | None. Code is not reloaded | <Status issue={316} /> | Only data pack reload is planned |
| NMS, CraftBukkit | Any public crate of the library layers | <Status issue={437} /> | There is no facade between you and the engine, so these crates are NMS and API at once |
| Static `Bukkit.getServer()` | None. Take `Res<T>`, `Query<..>`, `Commands` as system parameters | <Status issue={437} /> | The static accessor was rejected |
| Dependency on `paper-api` | A git dependency on mcrs crates | <Status issue={321} /> | One game version at a time, no backward compatibility (<Status issue={412} />) |

## Events

| JVM | mcrs | State | Notes |
|---|---|---|---|
| `Listener`, `@EventHandler` | An observer `app.add_observer(f)` with `f: fn(On<Event>)`, or `MessageReader<M>` for a message buffer | <Status issue={283} /> | The hook depends on the domain: chat and commands have `cancelled`, inventory has `RequestCheck`, and damage has a filter set. Packet observers use `Received<P>` |
| `setCancelled(true)` | The `cancelled` field of the event, set in an observer that takes `mut` | <Status pr={636} state="partial" /> | Only `PlayerChatEvent` and `CommandEvent`. A general mechanism with rollback of client prediction is <Status issue={283} /> |
| `AsyncChatEvent` | `PlayerChatEvent { player, text, cancelled }` | <Status pr={636} state="works" /> | `text` is a `Text` component, not a `String`. It fires before the broadcast |
| `EventPriority` | System order: `.before()`, `.after()`, `SystemSet` such as `TickSet` | <Status issue={323} /> | Observers have no priority. An unordered conflict fails a test |
| `PlayerJoinEvent`, `PlayerQuitEvent` | Internal bus messages `InboundPlayerSpawn` and `InboundPlayerDespawn` | <Status issue={283} /> | Not a public event yet. Public join and leave events are planned |
| `BlockBreakEvent`, `BlockPlaceEvent` | The public message `UseItemOnRequest` for a placement, and the public set `BlockBreakSet` to order a system after the breaks | <Status issue={283} /> | No cancellable event yet. The break request is internal, and a placement can be refused only by replacing `VanillaBlockPlacePlugin`. See [Hook into block placing, breaking and drops](/docs/en/plugins/blocks/) |
| `InventoryClickEvent`, `setCancelled(true)` | An observer of `RequestCheck` that calls `deny(Denial { source, code })`, or a `Gate` in the `SlotPolicy` of the holder | <Status pr={846} state="works" /> | A click arrives as an inventory request. The denial carries the request source of your plugin. A click on a menu button arrives as `EntryPressed`. See [Inventory](/docs/en/plugins/inventory/) |
| `EntityDamageEvent` | A system in `DamageSet::Filter` edits or removes `DamageRequest` values in `PendingHits` | <Status pr={1078} state="works" /> | Applies to mobs and players. `Damaged` reports an accepted hit; see [Read player data](/docs/en/plugins/players/#health-damage-and-death) |
| `PlayerDeathEvent` | Read `Died`; replace `VanillaDeathDropsPlugin` or `VanillaDeathMessagesPlugin` | <Status pr={1084} state="works" /> | Write custom death text as `DeathMessage` in `PlayerDeathSet::Describe`. [Inventory](/docs/en/plugins/inventory/#inventory-on-death) covers drops and `keep_inventory` |
| `PlayerRespawnEvent` | Write `RespawnRequest { player, dimension, transform }` in the player's world | <Status pr={1082} state="works" /> | Replace `VanillaRespawnPlugin` to choose the destination; this is a request, not a cancellable event |
| `Bukkit.createInventory`, `openInventory` | A `MenuLayout`, obtained from `MenuLayout::of(MenuType::Generic9x3)` as `Some(layout)`, over a holder entity with `Slots`, opened with `open_titled_menu` of `MenuCommandsExt` | <Status pr={977} state="works" /> | Button entries in `MenuButtons` move no stack and write `EntryPressed`. `close_menu` replaces `closeInventory`. The mcrs client draws the eight generic container screens and takes clicks in them (<Status issue={130} />). See [Inventory](/docs/en/plugins/inventory/) |
| `ProtocolLib`, packet listeners | `On<Received<P>>` over the typed game packets | <Status state="partial" /> | About half of the packets are typed, see the README. One typed receive path: <Status issue={57} /> |
| Minestom `EventNode` tree | No event tree, only Bevy observers and schedules | <Status state="undecided" /> | There is no issue. Do not copy the pattern |

## Scheduler

| JVM | mcrs | State | Notes |
|---|---|---|---|
| `runTaskTimer` | A system in `FixedUpdate`, 20 ticks per second by default (`DEFAULT_TPS`) | <Status state="works" doc="crates/mcrs_minecraft_engine_server/src/runner.rs" /> | Keep state in a resource or `Local<T>`. Bevy does the scheduling, and mcrs has no scheduler of its own |
| `runTaskLater` | A counter or timer in a resource or component, or `Res<Time<Fixed>>` | <Status state="works" /> | You write it by hand, there are no helpers |
| `runTask` to return to the main thread | Not needed. There is no main thread in the Bukkit sense | <Status issue={357} /> | See [From objects to data](/docs/en/plugins/mental-model/) |
| `runTaskAsynchronously` | Bevy task pools exist, but there is no documented pattern for plugins | <Status state="partial" /> | There is no issue. Parallelism comes from the scheduler |

## Players and worlds

| JVM | mcrs | State | Notes |
|---|---|---|---|
| `Player`, `Entity` as objects | An `Entity` id plus components `Player`, `GameProfile`, `PlayerGameMode`, `Transform` and `Vitals`; mobs are entities too | <Status pr={1082} state="works" /> | `Entity` is local to one world, `PlayerSession` survives dimension travel, the profile UUID survives reconnects, and packets use a separate network id (<Status issue={158} />) |
| `player.sendMessage(Component)` | An `OutboundPlayerPacket` message, built with `bus::to` and the `system_chat` helper | <Status state="partial" /> | This is low level, and there is no `player.send()` |
| `Bukkit.getOnlinePlayers()` | `Query<&GameProfile, With<Player>>` inside a dimension | <Status state="partial" /> | Players live in dimension worlds, and there is no global collection (<Status issue={154} />) |
| `world.getBlockAt(..).setType(..)` | The `BlockSetRequest` message and the `WorldView` volume API | <Status state="partial" /> | Works inside one dimension. One API for world access is <Status issue={486} /> |
| `World` and `createWorld` for mini games | Dimension worlds are fixed at start | <Status issue={546} /> | Creating and removing a world at run time is planned |
| Minestom `Instance` | A dimension world (a sub-app) | <Status issue={280} /> | Add plugins with `add_dimension_plugin`, not `add_plugins` |
| `ChunkGenerator` | A replaceable chunk source | <Status issue={281} /> | Today the generator is the vanilla one |
| Saving the world, `world.save()` | No call. The server writes changed chunks to the region files on an autosave every 6000 ticks and on a clean shutdown | <Status state="works" /> | Saving is not a method that a plugin calls |
| Boss bar | None | <Status issue={247} /> | |
| Scoreboard | None. Only the planned owner of global state names scoreboards | <Status issue={154} /> | There is no scoreboard issue, and we found no code |

## Commands and permissions

| JVM | mcrs | State | Notes |
|---|---|---|---|
| Brigadier, `registerCommand` | `add_command`, a typed command tree, literal and argument nodes | <Status pr={579} state="works" /> | The vanilla commands are the reference |
| Tab completion and the commands packet with levels | The command tree with permission levels and the commands packet | <Status issue={285} /> | See [Add a command](/docs/en/plugins/commands/) |
| `hasPermission("x.y")` | `PermissionCheck::Require(CommandLevel::..)`, operator level 0-4 in `PlayerOpLevel` | <Status issue={285} /> | No string permission nodes, no LuckPerms-like plugin |
| Whitelist, ban list | A ban list resource and the `/ban` and `/whitelist` commands | <Status state="works" doc="crates/mcrs_minecraft_server/tests/it/ban.rs" /> | Covered by tests in `ban.rs` and `whitelist.rs` |
| A custom argument type | Added only at compile time, as part of the command set | <Status issue={285} /> | |

## Data and config

| JVM | mcrs | State | Notes |
|---|---|---|---|
| `config.yml`, `saveDefaultConfig()` | Fields on the plugin struct. The binary reads `MCRS_*` environment variables | <Status state="partial" /> | Configuration comes only through the plugin (<Status issue={278} />). The settings of the binary are in [server_settings.rs](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server_settings/src/server_settings.rs). There is no config file format for a plugin yet |
| `PersistentDataContainer` | Your own component, registered with `register_persisted` | <Status issue={159} /> | Only components of players are saved. [Keep a player component across restarts and moves](/docs/en/plugins/persisted-components/) shows how to register one and choose whether the server writes it to the player file |

## Network and proxy

| JVM | mcrs | State | Notes |
|---|---|---|---|
| Velocity `ProxyServer`, `@Subscribe` | A proxy library without Bevy: routing, online mode, modern forwarding, backend switch | <Status issue={296} /> | Not in the code yet |
| Paper `proxies.velocity`, modern forwarding | The `forwarding` field of `ServerNetworkPlugin` with a `ForwardingSecret`. The binary reads `MCRS_FORWARDING` and `MCRS_FORWARDING_SECRET` | <Status pr={855} state="works" /> | [Connections, proxies and operators](/docs/en/server/connections/#put-the-server-behind-velocity) says what the player gets and when the binary does not start |
| Paper `proxies.proxy-protocol` | The `proxy_upstreams` field of `ServerNetworkPlugin`. The binary reads `MCRS_PROXY_UPSTREAMS`, IP addresses separated by commas | <Status pr={927} state="works" /> | [Connections, proxies and operators](/docs/en/server/connections/#read-the-player-address-from-a-proxy-header) says which connections must send a header and what the server takes from it |
| Online mode, Mojang authentication | None. The server is offline only | <Status issue={82} /> | Do not expose the port |
| ViaVersion | Protocol translation at the network edge, down to 1.21.6 | <Status issue={537} /> | The decision is open |
