This page is the change log of mcrs. Each entry says what was merged, what changed for people who write plugins, and what is still missing. A change is marked "Breaking" when old plugin code stops compiling. The newest entry comes first.

## Since v0.5.8 (no tag yet)

This entry covers 2026-10-14 to 2026-11-23. In that time 385 pull requests from 14 authors were merged, 277 from andreypfau and 108 from 13 other people. The main history since v0.5.8 contains 1134 commits.

### Merged

- Mobs now run as ECS entities with motion and attributes, plus a brain component where supported; the old mob row path is removed (<Status pr={1069} state="works" />, <Status pr={1073} state="works" />, <Status pr={1075} state="works" />, <Status pr={1077} state="works" />).
- A sorted hit queue applies mob damage after the motion pass, with armour, damage immunities and health updates for resting mobs (<Status pr={1078} state="works" />).
- Players have health, can take command damage, die and respawn at the world spawn. Death drops inventory items and sends a chat message according to the game rules; cursor and crafting-grid stacks drop separately when the dead player is removed or respawns (<Status pr={1082} state="works" />, <Status pr={1084} state="works" />).
- The native client shows health and food bars and a death screen. The Respawn and Title Screen buttons wait 20 ticks; the browser entry point does not add these GUI plugins (<Status pr={1085} state="works" />).
- The client draws name tags above players and named mobs, and sign text no longer shows mirrored from behind its plane (<Status pr={1062} state="works" />, <Status pr={1056} state="works" />).
- Observers receive player arm swings for punches, piercing-weapon stabs, accepted block placement and hand drops. A pure swing kernel and typed item animation components supply the cooldown and animation data. The `/swing` specification exists, but the command is not registered (<Status pr={1012} state="works" />, <Status pr={1063} state="works" />, <Status pr={1064} state="works" />).
- The native window opens while block definitions load in the background. Data-pack preparation still happens before the window opens (<Status pr={1057} state="works" />).
- World generation reuses climate searches and density work. Block and biome hashes stayed identical at the three benchmark locations, and new benchmarks measure per-stage CPU time and generation from load tickets to loaded sections (<Status pr={1065} state="works" />).
- Client knowledge and reach now have specifications and a lag compensation design note. Their experiments have not run, and the proposed system is not implemented (<Status pr={1086} state="works" />).
- Outside contributions follow the issue, scope and evidence rules in `CONTRIBUTING.md`. The PR body lists every model used and what it did (<Status pr={1070} state="works" />, <Status pr={1071} state="works" />).
- Worlds tick as parallel cells behind a muxer thread and a shared data layer (<Status pr={646} state="works" />).
- The server has mobs with a parallel AI stage, the client renders mobs (<Status pr={651} state="works" />).
- Entity physics, movement checks and block simulation work (<Status pr={648} state="works" />), and so do the block tick and block event queues (<Status pr={477} state="works" />).
- Player bans and the whitelist follow their specifications (<Status pr={637} state="works" />, <Status pr={635} state="works" />).
- The server disconnects and saves every player before shutdown (<Status pr={624} state="works" />).
- The server writes changed chunks back to their region files, and a clean shutdown saves the world (<Status issue={78} />).
- The server saves worlds and players. An autosave runs every 6000 ticks, a region it cannot read goes to a quarantine folder, the state of structures survives a restart, and a clean shutdown saves the players (<Status pr={744} state="works" />). The player file keeps the attributes of a player too (<Status pr={851} state="works" />).
- The server opens a folder without `level.dat` as a new world and locks the world folder through `session.lock` (<Status pr={969} state="works" />).
- A player can break blocks in creative mode (<Status pr={643} state="works" />), and in survival mode with an empty hand (<Status pr={735} state="works" />). A player can place a block item on the face of a block (<Status pr={770} state="works" />), and a block that loses its support breaks (<Status pr={774} state="works" />). Falling blocks fall (<Status pr={798} state="works" />).
- Item stacks are typed values, and a dropped stack becomes an item entity that the server replicates (<Status pr={704} state="works" />, <Status pr={705} state="works" />, <Status pr={749} state="works" />). `/summon` can make an item entity (<Status pr={750} state="works" />), and a broken block drops the items of its loot table (<Status pr={768} state="works" />).
- The player inventory works on the server from its specification. The vanilla inventory plugin handles clicks, drops, the selected hotbar slot and the creative slot, and saves the inventory in the player file (<Status pr={759} state="works" />, <Status pr={767} state="works" />, <Status pr={846} state="works" />, <Status pr={954} state="works" />).
- Menus are data. A plugin opens a menu with a title and button entries over any holder, and a press on a button entry arrives as a message (<Status pr={977} state="works" />). An equippable item enters its armour slot by a click and by a quick move, and an enchantment that locks armour keeps it there outside creative mode (<Status pr={986} state="works" />, <Status pr={988} state="works" />). Each plugin denies inventory requests with a request source of its own (<Status pr={988} state="works" />).
- The server tracks the pose of each player and sends it to the other players. The box and the eye height of a player follow the pose, the camera of the client follows the eye height, and the client draws other players sneaking, swimming, crawling, sleeping, gliding and in a spin attack (<Status pr={970} state="works" />).
- The item stack has typed values for 19 more data components, among them the dyed colour, trims, potions, custom data, bundles, containers, fireworks, banner patterns and bees (<Status pr={992} state="works" />, <Status pr={993} state="works" />).
- Enchanted books and painting variants have typed components with saved, wire and hashed forms. The client can send them from creative content. Stack readers and writers reject a saved NBT tree deeper than 512 levels; inline painting variants are still refused (<Status pr={1018} state="works" />).
- The server limits the NBT that one serverbound packet or one stack may carry, by charged bytes and by tags, and it disconnects a client whose packet goes over the limit (<Status pr={1006} state="works" />).
- Loot tables evaluate every condition, every number provider, weighted entries, and the count, damage, enchantment and attribute modifiers of items (<Status pr={841} state="works" />, <Status pr={850} state="works" />, <Status pr={857} state="works" />, <Status pr={862} state="works" />, <Status pr={866} state="works" />). The item, block, entity and location predicates match (<Status pr={838} state="works" />, <Status pr={843} state="works" />, <Status pr={847} state="works" />, <Status pr={854} state="works" />, <Status pr={858} state="works" />).
- Entities have attributes with modifiers on the server and on the client, and the server sends them to the client (<Status pr={783} state="works" />, <Status pr={788} state="works" />, <Status pr={793} state="works" />). Cows, sheep and chickens get the goals of the pig (<Status pr={773} state="works" />).
- The server accepts players forwarded by Velocity modern forwarding (<Status pr={855} state="works" />) and the PROXY protocol from trusted upstreams (<Status pr={927} state="works" />). It limits the number of players, the joins per address, the join rate and the packet rate (<Status pr={939} state="works" />). A player who joins from a loopback address is an operator only on the local profile, and the server binary uses the public one (<Status pr={933} state="works" />).
- The client has a pause menu and option screens. The video settings change the render distance, the frame limit, vsync and fullscreen while the client runs (<Status pr={747} state="works" />, <Status pr={748} state="works" />, <Status pr={757} state="works" />, <Status pr={760} state="works" />).
- The client opens a title screen at start. Singleplayer lists the worlds of the game directory, creates, deletes and opens one, and Save and Quit to Title saves the world (<Status pr={974} state="works" />).
- Outside creative mode, E opens the player inventory with the stacks of the server and the figure of the player (<Status pr={780} state="works" />, <Status pr={789} state="works" />), and the mouse wheel and the keys 1 to 9 select a hotbar slot (<Status pr={945} state="works" />).
- The client keeps the stacks of the local player in the same item holders as the server and draws the item icons from them (<Status pr={991} state="works" />, <Status pr={996} state="works" />). A client without a GUI predicts and sends its clicks and holds the container menus that the server opens (<Status pr={994} state="works" />, <Status pr={1003} state="works" />). In the inventory screen the mouse and the keys move stacks, and outside a screen Q drops and F swaps the hands (<Status pr={1004} state="works" />).
- The client draws the eight generic container screens a server opens, with resource-pack textures, titles and slots (<Status pr={1016} state="works" />). Menu screens preview a drag and gather stacks with a double click, including the Shift variants (<Status pr={1025} state="works" />), and show an item tooltip on hover (<Status pr={1024} state="works" />).
- In creative mode E opens the creative inventory with tabs, scrolling, text and tag search, the hotbar row and the survival inventory tab with a destroy slot (<Status pr={1029} state="works" />, <Status pr={1046} state="works" />). Its tab lists come from the generated report and the session, and a client without a GUI can send creative clicks (<Status pr={1008} state="works" />).
- F3+F4 shows the game modes with item icons (<Status pr={1020} state="works" />). Hotbar, menu and cursor icons use that same item icon path, and a registry change refreshes a trimmed item icon (<Status pr={1030} state="works" />). A potion icon has the colour of its potion, and an enchanted item has the glint (<Status pr={1040} state="works" />).
- The client inventory, the container screens and the creative inventory have specifications (<Status pr={975} state="works" />, <Status pr={978} state="works" />), and a recording of the vanilla client confirms what the client changes on a drop and a hand swap (<Status pr={976} state="works" />). The update tool writes the stacks of each creative tab from a run of the game, and `mcrs_minecraft_creative_report` reads them (<Status pr={1002} state="works" />).
- The client draws the fog of the world with an Improved Transparency option (<Status pr={771} state="works" />), only the sections inside the render distance (<Status pr={762} state="works" />), the text of signs (<Status pr={698} state="works" />), every glyph of the default font (<Status pr={701} state="works" />), and players with the skin of their profile (<Status pr={758} state="works" />).
- The client moves the local player with the movement kernel of the server (<Status pr={807} state="works" />), and it moves items, falling blocks, primed TNT and experience orbs between two updates of the server (<Status pr={805} state="works" />).
- The browser client draws the world over WebGL2 as well as WebGPU (<Status pr={731} state="works" />), and it draws mobs and sign text over WebGPU (<Status pr={769} state="works" />, <Status pr={799} state="works" />). On Linux the client runs on Wayland as well as X11 (<Status pr={826} state="works" />).
- End columns get the biomes of the end source (<Status pr={717} state="works" />), and three changes make world generation faster (<Status pr={718} state="works" />, <Status pr={721} state="works" />, <Status pr={732} state="works" />).
- The first Bedrock Edition crates read and write the wire format, batches, the handshake and some game packets (<Status pr={690} state="works" />). Text and player identity have Bedrock crates too (<Status pr={689} state="works" />, <Status pr={719} state="works" />).

### Breaking for plugin authors

A plugin here is Rust code that is compiled into the server.

- `EntityKey` becomes `EntityUuid` over `uuid::Uuid`, with the same numeric ordering. The separate engine-world UUID component is removed (<Status pr={1068} state="works" />).
- `mcrs_minecraft_entity_rows` and `mcrs_minecraft_engine_mob_replication` are removed. Query mob components and use the moving-entity replication path. Player health fields leave `PlayerFileState` and are saved as `Vitals` through the persisted registry (<Status pr={1077} state="works" />, <Status pr={1082} state="works" />).
- `MinecraftServerPlugin` became the plugin group `MinecraftServerPlugins`, with members such as `ServerCorePlugin`, `DimensionWorldsPlugin`, `WorldGenPlugin` and `ServerNetworkPlugin`. You can disable or replace any member (<Status pr={551} state="works" />). The engine members then moved to the new crate `mcrs_minecraft_engine_server`, and `mcrs_minecraft_server` keeps the vanilla group (<Status pr={592} state="works" />).
- No library crate reads the environment or the working directory for settings now. Operators are an `ops` field of the plugin, and the client knobs are a `Knobs` resource (<Status pr={548} state="works" />). The details are in [Environment variables](/docs/en/reference/env-vars/).
- `Text::to_legacy_lossy` is removed. Use `plain_text` or `legacy_text` from `mcrs_minecraft_text_flatten`, which also take a `Language` (<Status pr={680} state="works" />).
- The reader and the writer of `mcrs_minecraft_nbt` lost the `_be` suffix of their methods, so `get_u8_be` is `get_u8` now (<Status pr={679} state="works" />).
- The workspace moved from Bevy 0.19.1 to 0.20.1, so a plugin moves too. An observer writes `On<Remove<X>>` in place of `On<Remove, X>`, and the same goes for `Add`, `Insert` and `Discard` (<Status pr={709} state="works" />).
- The loot table and context registries moved to `mcrs_minecraft_loot`, the damage type and mob effect registries to `mcrs_minecraft_entity`, the recipe registries to the new crate `mcrs_minecraft_recipe`, and the menu registry to the new crate `mcrs_minecraft_menu`. The names stay, and only the paths change (<Status pr={703} state="works" />).
- `PlayerDat` of `mcrs_minecraft_save` holds the NBT root of the player file and has the methods `pos`, `rotation` and `dimension` in place of typed fields (<Status pr={744} state="works" />).
- `PlayerHolders`, the slot policy for player holders and the restore systems moved to the new crate `mcrs_minecraft_player_holders`, and `PlayerItemFilePlugin` moved to `mcrs_minecraft_vanilla_inventory` (<Status pr={983} state="works" />). `Click`, `ClickKind` and `Clicked` moved to the new crate `mcrs_minecraft_container_click`, and `ServerboundContainerClick` carries them in one `click` field (<Status pr={985} state="works" />). `PlayerGameMode` moved to `mcrs_minecraft_game_mode` (<Status pr={988} state="works" />).
- The plain value `MenuLayout` replaces `InventoryMenu` and `MenuSlot`, and `close_menu` of `MenuCommandsExt` replaces the one of `PlayerInventoryCommandsExt` (<Status pr={977} state="works" />). `PlayerItemsRestored` is removed (<Status pr={986} state="works" />).
- `RequestSource` has a private field, so a plugin gets one only from `allocate_request_source`, and `RequestId` is `{ source, serial }` (<Status pr={988} state="works" />).
- `MenuType` and the menu registry key moved from `mcrs_minecraft_inventory_menu` to `mcrs_minecraft_menu_key`. `RequestPurpose` and its `serial()` replace the five `*_REQUEST` constants of `mcrs_minecraft_vanilla_inventory`. The play-state packet crate no longer links the inventory layout or rules (<Status pr={1037} state="works" />).
- Baked item model nodes hold a `ModelId`, and `Evaluator` takes an `ItemModelContext` value (<Status pr={1015} state="works" />). `MenuAction::Creative` carries a stack, so `MenuAction` and `MenuInput` no longer implement `Copy` or `Eq` (<Status pr={1008} state="works" />).
- `Screen::Menu` replaces `Screen::Inventory` (<Status pr={1016} state="works" />). `SlotIconPlugin` and `SlotIcon` replace the removed `ItemRenderPlugin` and per-entity `ItemRenderLayers` (<Status pr={1030} state="works" />).
- `ItemPlugin` takes no item table, and `ItemTable` is a resource that exists while stacks can be made (<Status pr={991} state="works" />). `mcrs_minecraft_item` lost the stack-as-entity model: `Held`, `Holds`, `SlotTable`, `StackRevision`, `DroppedItem` and `Thrower` (<Status pr={996} state="works" />).
- The fixed width, height and eye height of a player are gone, and the server reads them from the pose (<Status pr={970} state="works" />).

### New for plugin authors

- `DamagePlugin` exposes the `DamageSet` phases, `PendingHits`, `DamageRequest`, `Damaged` and `Died`. `PlayerVitalsPlugin` adds the player side, while a host supplies `RespawnRequest`; removable vanilla plugins handle respawn, death drops and death messages (<Status pr={1078} state="works" />, <Status pr={1082} state="works" />, <Status pr={1084} state="works" />).
- A headless client reads `Vitals`, `FoodLevel`, `PlayerKilled` and `EntityDamaged`, and writes `RequestRespawn`. `HealthHudPlugin` and `DeathScreenPlugin` add the GUI separately. `ClientRegistriesPlugin.defer_definitions` selects background block-definition loading and has no environment variable (<Status pr={1085} state="works" />, <Status pr={1057} state="works" />).
- A plugin can add plugins to every dimension world with `add_dimension_plugin`, or to one dimension world with `add_dimension_plugin_to` (<Status pr={552} state="works" />).
- The chat event is cancellable. An observer can stop a line or replace its text before the broadcast (<Status pr={636} state="works" />, part of <Status issue={283} />). Join, leave, movement and block events are not done.
- A plugin saves a component in the player file with `register_persisted` of `PersistedAppExt`, for the host and every dimension world in one call (<Status pr={744} state="works" />).
- A block placement arrives as the public message `UseItemOnRequest`, and the break systems are the public set `BlockBreakSet` (<Status pr={770} state="works" />). Every inventory packet arrives as one public `InventoryInput` message (<Status pr={767} state="works" />).
- `ServerNetworkPlugin` has the fields `forwarding`, `proxy_upstreams`, `join_limits`, `profile` and `nbt_budget` (<Status pr={855} state="works" />, <Status pr={927} state="works" />, <Status pr={939} state="works" />, <Status pr={933} state="works" />, <Status pr={1006} state="works" />).
- A plugin opens a menu over any holder with `open_menu` or `open_titled_menu` of `MenuCommandsExt` and reads `EntryPressed`, `MenuOpened` and `MenuClosed` (<Status pr={977} state="works" />). `MenuLayout::of` builds the generic container menus (<Status pr={1003} state="works" />).
- A plugin gets a request source of its own with `allocate_request_source`, and a denial names the source of the plugin that denied it (<Status pr={988} state="works" />).
- A client or a bot clicks and closes a menu with `MenuInput` and drops or swaps the hands with `HandInput` of `mcrs_minecraft_inventory_client`, and `Click::from_input` turns a mouse gesture into a click (<Status pr={994} state="works" />). The `extend_server` field of `LocalServerPlugin` adds plugins to the local server of the client (<Status pr={1003} state="works" />).
- `mcrs_minecraft_creative_content` builds and filters creative tab lists without Bevy, and `mcrs_minecraft_item_tooltip` appends the text parts of a tooltip from caller-supplied inputs (<Status pr={1008} state="works" />, <Status pr={1024} state="works" />). `mcrs_minecraft_item_icon` resolves a stack into an `ItemIcon` value without a client or server dependency; `models_over_caps` reports model keys that exceed its layer or tint limits (<Status pr={1020} state="works" />, <Status pr={1038} state="works" />).
- `mcrs_minecraft_nbt` has `depth_of`, `NbtTag::depth` and `NbtCompound::depth` to measure NBT depth (<Status pr={1018} state="works" />).
- `DragSplit`, `DragEntry` and `EntryPreview` expose drag preview counts in `mcrs_minecraft_inventory_click`, and `shift_double_click_moves` selects matching entries for the Shift gesture. Implementations of `Slots` now supply `same_holder` (<Status pr={1025} state="works" />).
- `ServerThread` runs a server App on its own thread, and its owner asks it to save and stop (<Status pr={969} state="works" />).
- A program with no server adds a player with `host_living_entity` and gives it a model and a skin with `PlayerModel` and `PlayerSkin` (<Status pr={758} state="works" />).

### Not there yet

- Player melee attacks, own-player knockback and camera hurt tilt are missing. Respawn resets and resends remain incomplete, and beds and anchors are not used (<Status issue={106} />).
- There is no online mode (<Status issue={82} />).
- There is no loader for plugins outside the server build, and no decision on it.
- The creative screen has no saved hotbars (<Status issue={1032} />) and no player figure in the survival inventory tab (<Status issue={1043} />). [The client today](/docs/en/client/overview/#what-is-missing) lists the other screen, icon and tooltip limits.
