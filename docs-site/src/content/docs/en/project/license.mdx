## Mojang material

The README says the repository ships no Mojang art. The client reads textures and models from the official game jar of the player. Data tables and reports in `assets/` are regenerated from the game jar by one command, so moving to a new snapshot is mostly a data update.

## Clean-room

Behavior comes from specifications, not from the game's code. A spec author may read the game and writes down only behavior. An implementer reads only specs and artifacts that the game produces, and never reads decompiled or mapped game code. Names from the game's code stay out of the repository, except six community terms that the rule file lists: `ResourceKey`, `TagKey`, `BlockPos`, `SectionPos`, `ColumnPos` and `PalettedContainer`.

The full rule is [docs/clean-room.md](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md). If you have read the code of the game for some behavior, you cannot implement that behavior. Details: [How to contribute](/docs/en/contributing/).
