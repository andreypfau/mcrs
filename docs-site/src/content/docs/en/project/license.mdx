This page tells you under which licenses you can use mcrs, how the project relates to Mojang, and what rule keeps the game's code out of the repository. Read it before you fork the project, ship it in a product or send your first pull request.

## You choose between Apache 2.0 and MIT

mcrs is licensed under either of the [Apache License 2.0](https://github.com/andreypfau/mcrs/blob/main/LICENSE-APACHE) or the [MIT license](https://github.com/andreypfau/mcrs/blob/main/LICENSE-MIT), at your option. The workspace `Cargo.toml` says `license = "MIT OR Apache-2.0"`.

Code adapted from [valence](https://github.com/valence-rs/valence) keeps its own notice, the [MIT license of The Valence Authors](https://github.com/andreypfau/mcrs/blob/main/LICENSE-VALENCE-MIT).

## No affiliation with Mojang or Microsoft

mcrs is not affiliated with Mojang or Microsoft. Minecraft is a trademark of Mojang Synergies AB.

## Mojang material comes from the player's own game jar

The README says the repository ships no Mojang art. The client reads textures and models from the official game jar of the player. Data tables and reports in `assets/` are regenerated from the game jar by one command, so moving to a new snapshot is mostly a data update.

## Behavior is written from specifications (clean-room)

New contributions take the behavior of the game from written specifications under the clean-room rule. A specification author may read the game's code and records only behavior. An implementer reads specifications, public player-facing documentation, game artifacts and repository code permitted by the rule, and never reads decompiled or mapped game code.

Names from the game's code stay out of the repository. The rule file lists eight community terms as exceptions: `ResourceKey`, `TagKey`, `BlockPos`, `SectionPos`, `ColumnPos`, `PalettedContainer`, `LootContext` and `NumberProvider`. It also lets a tool that runs inside the game and drives the vanilla client, such as `tools/vanilla-client`, name the client classes it calls.

Existing world-generation code and its design notes have a [documented exception](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md#exception-world-generation). New work there follows the current rule, and a change that touches a name from the game's code removes that name.

If you have read the code of the game for some behavior, you cannot write the implementation of that behavior yourself. You can still deliver it through an AI agent that takes the implementer role, when you check that the specification is correct and the agent has no access to the game's code, in its files, its prompt or its tools. The full rule is [docs/clean-room.md](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md), and [How to contribute](/docs/en/contributing/) describes the roles.

The owner can also allow a named third-party open source implementation as a source for specification authors. GrimAC is allowed for lag compensation and reach. The same separation applies: implementers do not read that code, and its names, paths and quotations stay out of the repository. Rules from that source carry the label `design`, because they are choices of mcrs.
