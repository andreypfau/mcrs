Every number on this page comes from [PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md), and each one has its machine and scenario next to it. There is no comparison with vanilla, Paper or any other server here. We do not publish one until the benchmark in the last section runs on a quiet machine.

## The machine

All readings in `PERF.md` come from one machine: Apple M4 Max, 40 GPU cores, macOS, Metal. The main display is 3840x2160 at 60 Hz. The build is release, nightly Rust, Bevy 0.19.1, wgpu 29. Nothing was measured on Linux or Windows. A number from this page tells you what this machine did, not what yours will do.

## The rules

- A figure is the median of the settled lines of a run, not one frame and not a mean. The first ten seconds after launch are dropped.
- Spread between two runs of the same scenario is about 0.1 ms on the wall frame and 0.05 to 0.2 ms on a stage. A change smaller than that is noise.
- We quote engine CPU time, not fps. On macOS the wall frame includes the swapchain acquire, which waits for the display, so an empty scene reads 3.5 ms wall with 2.8 ms inside the acquire. The budget binds on the engine figure (wall minus acquire) and on GPU pass timestamps (`DECISIONS.md`, first entry).
- Engine time is read with `MCRS_HOT=1`. The knob keeps one core spinning, because the performance cores clock down while the frame sleeps. Without it the same empty frame reads 1.37 ms median and 4.0 ms p99, with it 0.60 and 1.12. The knob is off by default, and a player at vsync pays the clock ramp. Both numbers are in `DECISIONS.md`.
- Each decision in `DECISIONS.md` is one line with the numbers that justified it.

The goal for engine CPU time is 1.0 ms (`PERF.md`, Budget). `PERF.md` marks a reading above its ceiling as "over the ceiling", and this page keeps those lines.

## Client

Scenario for these rows: 2560x1440 window, `MCRS_HOT=1`, overlay hidden, save `two-relight`, default render distance 96 columns. Source: `PERF.md`, section Hardening.

| Scenario | Engine median / p99 / max | Note |
|---|---|---|
| Empty frame (no server, sky only) | 0.80 / 0.94 / 0.94 ms | The floor of the engine. |
| 96 columns, standing | 1.12 / 1.33 / 1.33 ms | 38,025 columns and 295,511 sections resident. |
| 96 columns, flight at maximum speed (`MCRS_FLY`), 120 s | 1.56 / 5.0 / 5.9 ms | The p99 tail is over the ceiling. Two known sources of the tail are not fixed. |

What these numbers hide:

- At 96 columns the frame is bound by the GPU, not the CPU. The GPU frame is 3.7 ms, above the 1.0 ms goal. The process holds about 12 GB, and the memory arenas sit at 50% of 4.3 GB (`PERF.md`, Render distance; that reading predates the occlusion pass, so the memory today can differ).
- The 96 column view takes about 80 s to settle with a 32 MB upload budget (`MCRS_UPLOAD=32`). With the 4 MB default it does not settle within four minutes.
- A settled view shows 0 KB of upload per frame. In flight it uploads 300 to 450 KB per frame.

## Not measured yet

- Memory per loaded section and per entity component. The README used to promise it, and `PERF.md` has no such table. <Status issue={324} /> says the number goes into `PERF.md` when a test counts it.
- The cost of an idle server tick, and a count of overrun ticks: <Status issue={320} />. Today the server loop starts the next tick at once after an overrun, with no count and no warning.
- Server tick time under load by players. A bot load exists (`crates/mcrs_minecraft_server/examples/tick_load.rs`), but its machine and conditions are not recorded, so we do not quote it.
- Anything on Linux or Windows.

## mob-bench: a method without results

`benchmarks/mob-bench` loads one server with 50,000 pigs and measures its tick, CPU use and the motion of the pigs. The harness is `tools/mob-bench`. It runs mcrs, a vanilla server of the same snapshot and one other Rust server through the same phases: idle, roaming, crowding, a stimulus (panic hits on some pigs) and the cost of the AI, each with and without a connected client.

The author marks the first session as provisional: every window was contended, because other builds ran on the machine at the same time (load average up to 84). The README says official runs need a quiet machine. So this page shows no result of it.

The full matrix takes about 2.5 hours on the M4 Max. To run it:

```sh
cargo build --release -p mcrs_mob_bench -p mcrs --bins
MINECRAFT_EULA=true tools/mob-bench/run.sh
```

The other server needs its own checkout and files, described in the bench README.

## How to repeat a client reading

```sh
MCRS_STATS=5 ./target/release/mcrs_minecraft_client "<world folder>"
```

This writes the F3 line to the log every five seconds with the overlay hidden. The knobs that shape a scenario (`MCRS_RESOLUTION`, `MCRS_SERVER`, `MCRS_FLY`, `MCRS_HOT`) are in [Environment variables](/docs/en/reference/env-vars/). They are not for normal play. Tracy captures need the `telemetry-tracy` feature.
