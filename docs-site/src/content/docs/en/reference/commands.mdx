The server registers 20 root commands (21 names with the alias `tp`). They come from two plugins: `VanillaCommandsPlugin` in `crates/mcrs_minecraft_command_vanilla` and `WorldCommandsPlugin` in `crates/mcrs_minecraft_command_world`. This list was checked against both `plugin.rs` files and the permission calls of each command on commit `51d45c26a`. Commands that vanilla has and that are not in this list do not exist here yet. `setblock`, `give`, `say` and `stop` are not registered, for example.

## Permission levels

There are five ordered levels, as in vanilla ([command-permissions spec](https://github.com/andreypfau/mcrs/blob/main/docs/spec/command-permissions.md), PERM-LEVEL-001).

| Id | Name |
|---|---|
| 0 | `all` |
| 1 | `moderators` |
| 2 | `gamemasters` |
| 3 | `admins` |
| 4 | `owners` |

A player who is not an operator has level `all`. An operator has the level that `ops.json` gives, from 0 to 4. The `op` command gives the default level, which is `owners`. A player who joins from the same machine is an operator for the session. Every command below needs level 2 or 3, so only operators can run them.

## Typing commands

A player types commands in chat. The server also reads its standard input: each line runs as a command of the server source, in the overworld (`ConsolePlugin` in `crates/mcrs_minecraft_console`). A burst of lines runs over several ticks, at most 2000 lines per tick. The answers go to the server log.

## For plugin authors

Commands are Bevy plugin code: a plugin calls `add_command` with a build function and a run function (see both `plugin.rs` files for the pattern), and a command can write effects that other systems apply. Commands also raise a cancellable `CommandEvent`. There is no loader for plugins that are not compiled into the server, and no decision about one yet. The page [Commands for plugins](/docs/en/plugins/commands/) has the details.
