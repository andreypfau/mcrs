## Can I use it yet?

Yes, if you are a developer who wants a base to build on, or if you want to watch the project. No, if you need a server for players. A vanilla client of the same snapshot can join in offline mode, chat, run {fact('root_commands')} commands and break blocks in creative. The server saves the world and the players, so your edits survive a restart. See [Run a server](/docs/en/start/run-server/) and [Status](/docs/en/start/status/).

## Will my plugins work?

No. Bukkit and Paper plugins do not load, and there is no facade API, because the project decided against one.[^437] A loader for plugins as jar files, wasm or scripts does not exist either, and there is no decision about one yet. Today your code is a Rust Bevy plugin that you build together with the server, as in Minestom, where you write `main` yourself. You have to rewrite a plugin for mcrs, because it cannot be ported. See [Not Paper](/docs/en/plugins/not-paper/) and [Paper to mcrs](/docs/en/plugins/paper-to-mcrs/).

## Why Rust?

Not because "it is faster". Rust gives memory safety without a garbage collector. Each Bevy system declares which data it reads and which it writes, and the Bevy scheduler uses this to run systems in parallel without locks. The scheduler checks access conflicts when it builds the system graph. The compiler does not. The numbers we measured are in [PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md), each with the machine and the scenario. See [Parallel tick](/docs/en/concepts/parallel-tick/).

## Another Rust server?

The server here is an application on top of a set of crates. The project differs in its process. Specifications come before code, the goal is parity with the real game, the measurement method is recorded and decisions are kept in the tracker. We publish no comparison with other servers.

## Does it run on Linux and Windows?

The author measured and ran everything on macOS, on an Apple M4 Max with Metal. CI runs lint, clippy, portability checks and tests on Ubuntu 24.04, without the crates that need a GPU. For Windows the code has a jar path, and nobody has checked it.

## Which game version?

One version, {fact('snapshot')}, which is set in `assets/minecraft/version.json`. Old clients and worlds of other data versions do not work, and there are no datafixers.[^388][^412] The plan is to translate older client versions at the network edge.[^537]

## Is it legal?

Specifications are written by someone who may look at the game. Code is written from the specifications and has no game class names in it. The exception is world generation code, which was written without this rule. Textures and models come from the official client jar on your machine, and the repository contains no Mojang art. See [Clean-room](/docs/en/contributing/clean-room/) and [`docs/clean-room.md`](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md).

## Is it safe to run?

Only on your own machine or on a trusted local network. The server has no authentication, so anyone can join under any name, and it listens on all network interfaces. Do not open the port to the internet.

## Are there binaries?

Not yet. They will exist, but there is no issue for them. Until then you build from source, as [Install the tools](/docs/en/start/install/) describes.

## Can I publish my own plugin as a crate, or use mcrs crates?

Crates are not on crates.io, but you can depend on a git commit.[^321] There are no library examples yet.[^287] See [Crates overview](/docs/en/crates/overview/).

## How do I follow progress?

Watch issues on GitHub, follow the tags feed or join [Discord](https://discord.gg/ged3nMRzwG). The [Status](/docs/en/start/status/#how-to-follow-progress) page lists every way.
