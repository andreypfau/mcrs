## Can I use it yet?

As a base for developers and for watching: yes. As a server for players: no. A vanilla client of the same snapshot can join in offline mode, chat, run 20 commands and break blocks in creative. The world is not saved after you leave, except players (<Status issue={78} state="wip" />). See [Run a server](/docs/en/start/run-server/) and [Status](/docs/en/start/status/).

## Will my plugins work?

No. Bukkit and Paper plugins do not load, and there is no facade API: the decision <Status issue={437} state="declined" /> rejects it. A loader for plugins as jar files, wasm or scripts does not exist, and there is no decision about one yet. Your code today is a Rust Bevy plugin built together with the server, like in Minestom where you write `main`. Plugins are rewritten, not ported. See [Not Paper](/docs/en/plugins/not-paper/) and [Paper to mcrs](/docs/en/plugins/paper-to-mcrs/).

## Why Rust?

Not because "it is faster". Rust gives memory safety without a garbage collector. Each Bevy system declares which data it reads and which it writes, and the Bevy scheduler uses this to run systems in parallel without locks. The scheduler checks access conflicts when it builds the system graph, not the compiler. Measured numbers are on [PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md), with the machine and the scenario. See [Parallel tick](/docs/en/concepts/parallel-tick/).

## Another Rust server?

The server here is an application on top of a set of crates. What is different is the process: specifications before code, parity with the real game, recorded measurement method, decisions kept in the tracker. We publish no comparison with other servers.

## Does it run on Linux and Windows?

The author measured and ran everything on macOS (Apple M4 Max, Metal). CI runs lint, clippy, portability checks and tests on Ubuntu 24.04, without the crates that need a GPU. Windows: the jar path exists in the code, nobody has checked it.

## Which game version?

One: 26.4-snapshot-7 (`assets/minecraft/version.json`). Old clients and worlds of other data versions do not work, and there are no datafixers (<Status issue={388} state="declined" />, <Status issue={412} state="declined" />). Translating older client versions at the network edge is a plan: <Status issue={537} state="wip" />.

## Is it legal?

Specifications are written by someone who may look at the game, and code is written from the specifications, without game class names in the code. The exception is world generation code, which was written without this rule. Textures and models come from the official client jar on your machine, and the repository contains no Mojang art. See [Clean-room](/docs/en/contributing/clean-room/) and [`docs/clean-room.md`](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md).

## Is it safe to run?

Only on your own machine or a trusted local network. There is no authentication, anyone can join under any name, and the server listens on all network interfaces. Do not open the port to the internet.

## Are there binaries?

They will exist. Not yet, and there is no issue for them. Until then you build from source: [Install](/docs/en/start/install/).

## Can I publish my own plugin as a crate, or use mcrs crates?

Crates are not on crates.io: <Status issue={321} state="undecided" />. You can depend on a git commit. There are no library examples yet (<Status issue={287} state="wip" />). See [Crates overview](/docs/en/crates/overview/).

## How do I follow progress?

Watch issues on GitHub, follow the tags feed, or join [Discord](https://discord.gg/ged3nMRzwG). Details: [Status](/docs/en/start/status/#how-to-follow-progress).
