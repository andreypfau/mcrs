This page lists what you need on your machine to build mcrs. If you come from Java, the second half maps the parts of Gradle you know to Cargo, the build tool of Rust.

<Aside type="caution" title="WIP">
A detailed install guide will come before the alpha. Today only developers use the project, so this page is short and we have not run its steps again for the docs. When in doubt, follow the [README Quick start](https://github.com/andreypfau/mcrs/blob/main/README.md#quick-start). Publishing the crates is a different piece of work.[^321]
</Aside>

## What you need

Install Rust through [rustup](https://rustup.rs). You do not pick a version, because [`rust-toolchain.toml`](https://github.com/andreypfau/mcrs/blob/main/rust-toolchain.toml) pins `nightly-2026-09-02` and rustup downloads it on the first `cargo` call. It also adds rustfmt, clippy, the wasm32 targets and the Cranelift code generator, which a debug build uses for most workspace crates.

On Linux the client supports both Wayland and X11.

For an IDE, use RustRover, or IntelliJ IDEA with the Rust plugin, and open the repository root as a Cargo project. Check the current licence terms of RustRover yourself.

mcrs needs the official client jar of the snapshot, but you do not download it by hand. It is taken from the launcher folder, or downloaded from Mojang into the same folder on the first run, and then checked by SHA-1. The client also needs the font files and the title screen panorama, which the game keeps outside the jar. It takes them from the `assets/objects` folder of the launcher or downloads them from Mojang into that folder, and checks each file by SHA-1.

The native client loads block definitions in the background, so the window can open before they are ready. An automatic join through `--connect` waits for those definitions. The web client still loads them synchronously.[^1057]

You do not need Java to run mcrs. The oracle and tools that launch vanilla need the Java version listed as `java_version` in [`version.json`](https://github.com/andreypfau/mcrs/blob/main/assets/minecraft/version.json).

The native client has been checked on Windows in a release build with a GTX 1080, including startup and joins to a local server.[^1057] CI runs checks on Ubuntu 24.04, and its default test profile skips GPU tests.

The `crates/` directory has {fact('crates')} crates. This guide gives no estimate for the duration or disk use of a first build.

## Cargo for people who know Gradle

| Gradle | Cargo |
|---|---|
| `settings.gradle` with subprojects | Root `Cargo.toml` with `[workspace]`. Members include packages in `crates/`, `tools/` and `examples/` |
| `build.gradle` of a project | `Cargo.toml` of a crate |
| `./gradlew run` | `cargo run`. For mcrs add `--release`, because a debug build is too slow |
| `./gradlew build` | `cargo build` |
| `./gradlew test` | `cargo test`. This repository uses `cargo nextest run` |
| Gradle wrapper pins the Gradle version | `rust-toolchain.toml` pins the compiler |
| `build/` folder | `target/` folder |
| Maven coordinates and a version | A crate name and a version, or a git URL with `rev` |
| Lock file of dependencies | `Cargo.lock`, committed |
| `implementation` and `api` scopes | `[dependencies]`. There is no `api` scope, and all `pub` items are visible |

Crates are not published on crates.io, so today your own code lives in a clone of the repository or depends on a git commit.[^321]
