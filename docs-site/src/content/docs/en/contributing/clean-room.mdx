mcrs builds the behavior of the game from descriptions of that behavior and never from the game's code.

- A specification author may read the game's code and writes the behavior into `docs/spec/`.
- An implementer reads the specification and never reads the game's code.
- No code, comment, test, note, commit message or issue names the game's classes, methods or fields.
- A parity test compares our output with artifacts that the game produced.

The rule is in [docs/clean-room.md](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md). That file is the authority. [Specs and parity](/docs/en/contributing/specs-and-parity/) describes the spec format.
