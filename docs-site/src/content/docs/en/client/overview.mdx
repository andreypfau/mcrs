mcrs has its own client, written in Rust on Bevy and wgpu. You can fly around a world with it and look at the terrain, the sky and the mobs, but you cannot play survival with it yet. This page is for a player or an observer who wants to know what the client does today, what it does not do, and what its long view costs in frame time and memory.

<StatusRows areas="client" />

## What the client does

| Feature | State |
|---|---|
| Terrain with the block models and light of the game | Works, and the light includes coloured block light |
| Sky, clouds and the fog of the environment | Works |
| Mobs | Works for pigs, frogs and players, the types that have a model in the entity pack of the repository. The client does not draw the other mob types of the server yet. The native client draws a player with the skin of its profile. The client draws far mobs as flat images, which [How the client renders](/docs/en/client/rendering/) explains |
| F3 overlay with frame and stage times | Works |
| Chat with command suggestions | Works |
| Breaking blocks in creative mode, and showing the block you aim at | Works |
| Title screen and local worlds | Works in the native client. The client opens the title screen at start. Singleplayer lists the worlds in the `saves` folder of the game directory, creates a new world, deletes one and opens one, and Save and Quit to Title saves the world and returns to the title screen |
| Inventory screen | Works. E opens it, and the mouse and the keys move stacks. The client predicts each click before the server answers, and the next packets of the server overwrite the prediction. Outside a screen Q drops one item of the selected stack, Control+Q drops the whole stack, and F swaps the hands |
| Hotbar | Works. The mouse wheel and the keys 1 to 9 select a slot, and spectator mode shows no hotbar |
| Pause menu and option screens | Works in the native client. Escape opens the pause menu. The video settings change the render distance, the frame limit, vsync and fullscreen while the client runs, and the client keeps the options in `options.json` in the game directory |
| Joining the mcrs server or an embedded one | Works. A vanilla client of the same snapshot can also join the mcrs server in offline mode |

## What is missing

| Feature | State |
|---|---|
| Sound | <Status issue={136} />. The client is silent |
| Particles | <Status issue={137} /> |
| Weather (rain, snow, lightning) | <Status issue={341} />. Today rain only dims the sun and the moon |
| Container screens and the creative inventory | The player inventory is <Status issue={521} />. Container screens are <Status issue={130} />. A client without a GUI already holds a container menu that the server opens, clicks in it and closes it, but the GUI does not draw one yet. The creative inventory is <Status issue={131} /> |
| A web build | <Status issue={344} />. Chrome draws the world over WebGPU and over WebGL2. On WebGL2 the browser draws no mobs, and the CPU and GPU times of the web build are not measured yet |
| Binary downloads | None yet. Releases are planned, and at this date no issue tracks them |

## The author checks one platform

The author checks the client on one platform, an Apple M4 Max with macOS and Metal. On Linux the client builds with both Wayland and X11, and a contributor ran it under Wayland when that support was added.[^826] Windows is not confirmed. CI on Ubuntu does not run the crates that need wgpu, so a green CI tells you nothing about those crates on Linux.

## A 96-column view

The client asks for 96 columns of view by default, where a column is a stack of 16x16x16 sections. That is three times the vanilla maximum of 32. The GPU limits the frame at this distance. The memory at 96 columns is not bounded yet.[^337] If your GPU or RAM is small, lower Render Distance in the video settings, or start the client with a smaller `MCRS_VIEW`, the number of columns it asks for.

## Build it from source to run it

There is no binary download, so you build the client from source. The steps are short and live in the repository, so this page does not repeat them. Follow the [README Quick start](https://github.com/andreypfau/mcrs#quick-start). The client starts on the title screen and runs its own server for the world you pick there. The game directory holds the worlds in `saves`, the options and the command history. It is `~/Library/Application Support/mcrs` on macOS, `$XDG_DATA_HOME/mcrs` or `~/.local/share/mcrs` on Linux and `%APPDATA%\mcrs` on Windows, and `MCRS_GAME_DIR` sets another folder. The other variables and options the client reads are on [Client variables](/docs/en/client/env-vars/). A world folder given as the argument is selected in the world list when it lies in `saves`. The client reads textures and models from the official game jar, because the repository ships no Mojang art.
