Эта страница для администратора, который хочет запустить сервер mcrs на каком-то мире. Сервер читает мир Java Edition той же версии игры и сохраняет игроков. Чанки он пока не сохраняет, поэтому любая правка блоков пропадает, когда сервер останавливается.

## Чтобы открыть мир Java, передайте папку мира

Передайте серверу папку первым аргументом. Как собрать и запустить сервер, показано в разделе [Quick start в README](https://github.com/andreypfau/mcrs#quick-start).

```bash
cargo run --release -- "<path to a world folder>"
```

Папка должна существовать, иначе сервер напечатает "not a world folder" и завершится. Когда папка указана, сервер берет сид и список измерений из настроек генерации мира в сохранении, а сид из `MCRS_WORLD_SEED` и пресет из `MCRS_WORLD_PRESET` их не переопределяют. Чанки сервер читает из файлов регионов сохранения, Java Edition хранит их в формате Anvil.

В каждом чанке и в каждом файле игрока записан `DataVersion`, номер версии игры, которая этот файл сохранила. Сервер принимает файл, только если этот номер совпадает с версией игры в этой сборке. Сейчас это <code dir="auto">{fact('snapshot')}</code> с версией мира 5127, она указана в [`version.json`](https://github.com/andreypfau/mcrs/blob/main/assets/minecraft/version.json). Файл любой другой версии сервер отклоняет с ошибкой, в которой названы найденная и ожидаемая версии. Чанк без `DataVersion` он тоже отклоняет.

## Старые миры не конвертируются

В mcrs нет конвертера для сохранений старых версий и не будет, потому что mcrs идет за одним снапшотом за раз и не держит цепочку совместимости. Так решено в <Status issue={388} />. Если у вас мир старой версии, откройте его один раз в ванильном клиенте нужного снапшота, чтобы игра его переписала, и только потом отдайте папку mcrs. По тому же решению поле, которое не заявил ни один тип, роняет загрузку, поэтому сервер не хранит такое поле как сырые байты.

## Без папки сервер генерирует мир

Если запустить сервер без аргумента, он сгенерирует мир из пресета. На диск из этого мира ничего не попадает. Файлов игроков у него тоже нет, потому что путь к файлу игрока сервер строит от папки мира. Мир задают три настройки, и сервер читает их один раз при старте. Полный список настроек лежит в [`server_settings.rs`](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server_settings/src/server_settings.rs).

| Переменная | Значение | По умолчанию |
|---|---|---|
| `MCRS_WORLD_SEED` | Сид, знаковое или беззнаковое 64-битное число | `0` |
| `MCRS_WORLD_PRESET` | `normal` или `minecraft:normal`, `flat` | `normal` |
| `MCRS_DEFAULT_GAMEMODE` | Режим игры нового игрока | `creative` |

Генерация мира совпадает с ванилью в parity-тестах на эталонных сидах. Что покрывают эти тесты, рассказывает страница [Parity](/docs/ru/concepts/parity/).

## Игроки сохраняются, чанки нет

| Данные | Состояние |
|---|---|
| Файлы игроков | Сохраняются. Сервер записывает каждого игрока в `players/data/<uuid>.dat` в папке мира при отключении, а автосохранение пишет их каждые 6000 тиков, с тем же интервалом, что и в ванили |
| Чистая остановка с игроками | <Status pr={624} state="works" />. По первому SIGINT или SIGTERM сервер отключает всех игроков с ванильной причиной остановки, сохраняет их и выходит. Второй сигнал завершает работу сразу |
| Чанки и правки блоков | Не сохраняются. Сервер читает чанки, но никогда их не пишет, см. <Status issue={78} /> |
| Чистая остановка с чанками | Не сделана. Ожидание записи чанков - это <Status issue={169} /> |
| `level.dat`, часы мира, погода, игровые правила | Читаются, но пока не записываются. Их запись перечислена в <Status issue={78} /> |

Файл игрока, который не удалось разобрать, сервер бережет. Игрок заходит с пустым состоянием, и сервер никогда не сохраняет его поверх старого файла. Инвентарь из файла игрока тоже не теряется. Сервер хранит его как непрозрачные данные и записывает обратно без изменений, потому что код инвентаря удален и переписывается по спецификации (<Status issue={521} />).

Чистую остановку проверяет короткий тест.

Сохранение чанков пока существует как план, кода для него нет. План описан в <Status issue={78} />. Сервер записывает измененные чанки в формате Anvil вне главного потока, при выгрузке и через интервалы, по одному писателю на файл региона. Пока этого нет, на работающем сервере mcrs можно посмотреть мир и что-нибудь попробовать. Хранить на нем мир нельзя.

## Датапаки загружаются один раз, при старте

При старте сервер загружает в реестры ванильный датапак и ваши локальные паки. Ванильный пак берется из jar игры, а локальный пак - это каталог внутри `mcrs/datapacks/` в корне ассетов сборки.

Пак можно проверить, не запуская сервер. Пример `check_pack` из крейта `mcrs_minecraft_game_registries` загружает ваш пак поверх ванильного, печатает все диагностики и завершается с ошибкой, если они есть.

```bash
cargo run -p mcrs_minecraft_game_registries --example check_pack -- "<data pack directory>"
```

В каталоге должны быть `pack.mcmeta` и `data/`, то же написано в строке usage инструмента.

Перезагрузить пак на работающем сервере нельзя, поэтому после изменения пака сервер нужно перезапустить. `/reload` и включение паков на лету запланированы в <Status issue={316} />. По плану перезагрузка заменяет данные на границе тика и отклоняет изменения, от которых зависит сохраненный мир, например высоту типа измерения.

Источника о том, как сервер обращается с папкой `datapacks` внутри папки мира, пока нет, поэтому страница ничего об этом не утверждает.
