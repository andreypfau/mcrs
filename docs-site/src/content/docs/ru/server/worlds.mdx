Эта страница для администратора, который хочет запустить сервер mcrs на каком-то мире. Сервер читает мир Java Edition той же версии игры и сохраняет мир и игроков. Измененные чанки возвращаются в файлы регионов из папки мира, поэтому правка блока переживает перезапуск.

## Чтобы открыть мир Java, передайте папку мира

Передайте серверу папку первым аргументом. Как собрать и запустить сервер, показано в разделе [Быстрый старт в README](https://github.com/andreypfau/mcrs#quick-start).

У сервера нет аутентификации, и он слушает все сетевые интерфейсы. Запускайте его на своей машине или в доверенной локальной сети; не открывайте порт в интернет.

```bash
cargo run --release -- "<path to a world folder>"
```

Папка должна существовать, иначе сервер напечатает "not a world folder" и завершится. Если в папке есть мир, сервер берет сид и список измерений из настроек генерации мира в сохранении, а сид из `MCRS_WORLD_SEED` и пресет из `MCRS_WORLD_PRESET` их не переопределяют. Режим игры для нового игрока в этом случае берется из `level.dat`. Если `level.dat` нет, а осталась только его резервная копия `level.dat_old`, сервер открывает мир из копии. Чанки сервер читает из файлов регионов сохранения, Java Edition хранит их в формате Anvil.

Папка, в которой нет ни `level.dat`, ни сохраненных настроек генерации мира, например пустая, становится новым миром. Сервер записывает в нее `level.dat` и настройки генерации мира по `MCRS_WORLD_SEED`, `MCRS_WORLD_PRESET` и `MCRS_DEFAULT_GAMEMODE`, поэтому при следующем запуске открывается тот же мир с тем же сидом.[^969]

Пока сервер работает, он держит блокировку файла `session.lock` в папке мира, как это делает игра. Если блокировку держит другой процесс, сервер ничего не пишет в папку и не запускается.[^969]

В `level.dat`, в каждом чанке и в каждом файле игрока записан `DataVersion`, номер версии игры, которая этот файл сохранила. Сервер принимает файл, только если этот номер совпадает с версией игры в этой сборке. Сейчас это <code dir="auto">{fact('snapshot')}</code> с версией мира 5127, она указана в [`version.json`](https://github.com/andreypfau/mcrs/blob/main/assets/minecraft/version.json). Файл любой другой версии сервер отклоняет с ошибкой, в которой названы найденная и ожидаемая версии. `level.dat` или чанк без `DataVersion` он тоже отклоняет.

## Старые миры не конвертируются

В mcrs нет конвертера для сохранений старых версий и не будет, потому что mcrs идет за одним снапшотом за раз и не держит цепочку совместимости.[^388] Если у вас мир старой версии, откройте его один раз в ванильном клиенте нужного снапшота, чтобы игра его переписала, и только потом отдайте папку mcrs. Поле, которое не заявил ни один тип, тоже роняет загрузку, поэтому сервер не хранит такое поле как сырые байты.[^388]

## Без папки сервер генерирует мир

Если запустить сервер без аргумента, он сгенерирует мир из пресета. На диск из этого мира ничего не попадает, и автосохранения нет. Файлов игроков у него тоже нет, потому что путь к файлу игрока сервер строит от папки мира. Мир задают три настройки, и сервер читает их один раз при старте. Полный список настроек лежит в [`server_settings.rs`](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server_settings/src/server_settings.rs).

| Переменная | Значение | По умолчанию |
|---|---|---|
| `MCRS_WORLD_SEED` | Сид, знаковое или беззнаковое 64-битное число | `0` |
| `MCRS_WORLD_PRESET` | Имя пресета мира в загруженном датапаке, например `normal`, `minecraft:normal` или `flat` | `normal` |
| `MCRS_DEFAULT_GAMEMODE` | Режим игры нового игрока | `creative` |

Генерация мира совпадает с ванилью в parity-тестах на эталонных сидах. Что покрывают эти тесты, рассказывает страница [Parity](/docs/ru/concepts/parity/).

## Сервер сохраняет мир

| Данные | Состояние |
|---|---|
| Файлы игроков | Сохраняются. Сервер записывает каждого игрока в `players/data/<uuid>.dat` в папке мира при отключении, а автосохранение пишет их каждые 6000 тиков, с тем же интервалом, что и в ванили |
| Чистая остановка с игроками | <Status pr={624} state="works" />. По первому SIGINT или SIGTERM сервер отключает всех игроков с ванильной причиной остановки, сохраняет их и выходит. Второй сигнал завершает работу сразу |
| Чанки и правки блоков | Сохраняются. Сервер записывает каждый измененный чанк обратно в его файл региона в папке мира, а автосохранение делает это каждые 6000 тиков |
| Чистая остановка с миром | По первому SIGINT или SIGTERM сервер еще и сохраняет все загруженные чанки и файлы состояния мира, а потом выходит. Если сохранение не удалось, статус выхода показывает ошибку |
| Файлы состояния мира | При старте сервер читает спавн, погоду, игровые правила, часы мира и настройки генерации мира из сохранения, а автосохранение пишет их обратно |
| Нечитаемые регионы | Чанк, который не удалось декодировать, или регион с поврежденным слотом сервер копирует в `<save>/quarantine/` перед заменой. Файл, который не удалось прочитать, остается на диске как есть |

Файл игрока, который не удалось разобрать, сервер бережет. Игрок заходит с пустым состоянием, и сервер никогда не сохраняет его поверх старого файла. Из файла, который удалось разобрать, сервер читает инвентарь, эндер-сундук, выбранный слот хотбара, экипировку и атрибуты игрока, а при сохранении записывает их обратно.[^521] Ключ формата, для которого в mcrs еще нет поведения, возвращается в файл без изменений.[^744]

Здоровье игрока тоже восстанавливается при входе и записывается при сохранении. Новый игрок без файла начинает с максимальным здоровьем.[^1082]

## Датапаки загружаются один раз, при старте

При старте сервер загружает в реестры ванильный датапак и локальные паки, выбранные через `ServerCorePlugin::local_packs`. Готовый сервер выбирает `mcrs` и `beta`. Ванильный пак берется из jar игры. Локальные паки лежат в `mcrs/datapacks/` в корне ассетов сборки, а папки пространств имен - прямо в корне каждого пака, без обертки `data/`. Остальные каталоги автоматически не включаются.

Пример `check_pack` из крейта `mcrs_minecraft_game_registries` печатает сообщения загрузчика реестров без запуска сервера и завершается с ошибкой, если среди них есть ошибки. Он принимает пак со стандартной структурой: `pack.mcmeta` и `data/`. На этом коммите он включает только входной каталог с именем `mcrs` или `beta`; остальные имена отфильтровываются, поэтому успешный выход не подтверждает корректность произвольного датапака.

Блок роняет то, что выдает его таблица лута, а сервер ищет эту таблицу по имени среди таблиц всех загруженных паков, поэтому таблица с тем же именем в локальном паке меняет дроп. При старте каждого мира измерения сервер проверяет таблицы и пишет в лог ошибку на каждую найденную проблему, например неизвестный предмет, отсутствующую таблицу или таблицу, которая ссылается сама на себя. Пример [`loot_validate`](https://github.com/andreypfau/mcrs/blob/main/examples/loot_validate/README.md) делает ту же проверку без сервера и печатает каждую проблему отдельной строкой.

Перезагрузить пак на работающем сервере нельзя, поэтому после изменения пака сервер нужно перезапустить. `/reload` и включение паков на лету запланированы.[^316] По плану перезагрузка заменяет данные на границе тика и отклоняет изменения, от которых зависит сохраненный мир, например высоту типа измерения.

Источника о том, как сервер обращается с папкой `datapacks` внутри папки мира, пока нет, поэтому страница ничего об этом не утверждает.
