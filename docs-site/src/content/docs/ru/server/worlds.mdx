Коротко: сервер умеет читать мир Java Edition той же версии игры и сохраняет игроков. Чанки он пока не сохраняет, поэтому любая правка блоков пропадает при остановке сервера.

<StatusRows areas="persistence" />

## Открыть мир Java

Передайте серверу папку первым аргументом. Как собрать и запустить сервер, написано в [README, Quick start](https://github.com/andreypfau/mcrs#quick-start).

```bash
cargo run --release -- "<path to a world folder>"
```

Папка должна существовать, иначе сервер напечатает "not a world folder" и завершится. Если папка указана, сид и список измерений сервер берет из настроек генерации мира в сохранении. Сид из `MCRS_WORLD_SEED` и пресет из `MCRS_WORLD_PRESET` их не переопределяют. Чанки читаются из файлов регионов Anvil в сохранении.

У каждого чанка и каждого файла игрока `DataVersion` должен совпадать с версией игры в этой сборке. Это версия <code dir="auto">{fact('snapshot')}</code>, версия мира 5127 (см. [`version.json`](https://github.com/andreypfau/mcrs/blob/main/assets/minecraft/version.json)). Файл любой другой версии отклоняется с ошибкой, в которой названы найденная и ожидаемая версии. Чанк без `DataVersion` тоже отклоняется.

## Нет datafixer

Конвертера из старых миров нет и не будет. Так решено в <Status issue={388} />: mcrs идет за одним снапшотом за раз и не держит цепочку совместимости. Если мир старой версии, откройте его один раз в ванильном клиенте нужного снапшота, чтобы игра его переписала, и только потом отдайте папку mcrs. То же решение говорит, что поле, которое не заявил ни один тип, роняет загрузку и не сохраняется как сырые байты.

## Новый мир

Без аргумента сервер генерирует мир из пресета. На диск из него ничего не попадает, а у мира без папки нет файлов игроков, потому что путь к файлу игрока строится от папки мира. Мир задают три настройки, и все они читаются один раз при старте (полный список в [`server_settings.rs`](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server_settings/src/server_settings.rs)).

| Переменная | Значение | По умолчанию |
|---|---|---|
| `MCRS_WORLD_SEED` | Сид, знаковое или беззнаковое 64-битное число | `0` |
| `MCRS_WORLD_PRESET` | `normal` или `minecraft:normal`, `flat` | `normal` |
| `MCRS_DEFAULT_GAMEMODE` | Режим игры нового игрока | `creative` |

Генерация мира совпадает с ванилью в parity-тестах на эталонных сидах. Что это покрывает, см. в разделе [Parity](/docs/ru/concepts/parity/).

## Что сохраняется сегодня

| Данные | Состояние |
|---|---|
| Файлы игроков | Сохраняются. Каждый игрок записывается в `players/data/<uuid>.dat` в папке мира при отключении, а также автосохранением каждые 6000 тиков, как в ванили |
| Чистая остановка с игроками | <Status pr={624} state="works" />. По первому SIGINT или SIGTERM сервер отключает всех игроков с ванильной причиной остановки, сохраняет их и выходит. Второй сигнал завершает работу сразу |
| Чанки и правки блоков | Не сохраняются. Сервер читает чанки, но никогда их не пишет: <Status issue={78} /> |
| Чистая остановка с чанками | Не сделана. Ожидание записи чанков - <Status issue={169} /> |
| `level.dat`, часы мира, погода, игровые правила | Читаются, но пока не записываются. Запись перечислена в <Status issue={78} /> |

Файл игрока, который не удалось разобрать, не перезаписывается: игрок заходит с пустым состоянием и никогда не сохраняется поверх старого файла. Если в файле есть инвентарь игрока, он хранится как непрозрачные данные и записывается обратно без изменений: код инвентаря удален и переписывается по спецификации (<Status issue={521} />).

Сохранение чанков - это план, а не код. Его описывает <Status issue={78} />: измененные чанки записываются в формате Anvil вне главного потока, при выгрузке и через интервалы, по одному писателю на файл региона. ## Датапаки

При старте сервер загружает в реестры ванильный датапак и локальные паки. Пак лежит в каталоге внутри `mcrs/datapacks/` в корне ассетов сборки, а ванильный пак берется из jar игры. Проверить пак без запуска сервера можно примером `check_pack` из крейта `mcrs_minecraft_game_registries`. Он загружает ваш пак поверх ванильного, печатает все диагностики и завершается с ошибкой, если они есть.

```bash
cargo run -p mcrs_minecraft_game_registries --example check_pack -- "<data pack directory>"
```

В каталоге должны быть `pack.mcmeta` и `data/`. То же написано в строке usage инструмента.

Перезагрузки во время работы сервера нет: чтобы изменить пак, нужен перезапуск. `/reload` и включение паков на лету запланированы: <Status issue={316} />. По плану перезагрузка заменяет данные на границе тика и отклоняет изменения, от которых зависит сохраненный мир, например высоту типа измерения.

Источника о том, как сервер обращается с папкой `datapacks` внутри папки мира, пока нет, поэтому страница ничего об этом не утверждает.
