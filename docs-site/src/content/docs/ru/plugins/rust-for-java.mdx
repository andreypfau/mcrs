Чтобы написать плагин, весь Rust учить не нужно. Здесь перечислено то, что используют туториалы. Java-сниппеты на этой странице только иллюстрируют идею, в mcrs их нет. Rust-сниппеты тоже короткие наброски, CI их не компилирует.

## Что нужно

| Rust | Идея из Java |
|---|---|
| `struct`, `enum` | `class` с полями, `enum`, который может нести данные |
| Блок `impl` | Методы класса |
| `trait` | `interface` |
| `Option<T>` | Значение, которое может быть `null` |
| `Result<T, E>` и `?` | Проверяемые исключения (checked exceptions) |
| `match` | `switch`, обязанный покрыть все случаи |
| Замыкание (closure) `\|x\| ...` | Лямбда |
| `Vec`, `HashMap`, `String` и `&str` | `List`, `Map`, `String` |
| `#[derive(Clone)]` | Сгенерированный код копирования и equals |
| `&T` и `&mut T` | Много читателей или один писатель, проверяется при компиляции |
| Модули, `use`, `Cargo.toml` | Пакеты, импорты, `build.gradle` |

## Владение коротко

У значения один владелец. Его можно одолжить как `&T` (много читателей) или как `&mut T` (один писатель), но не обоими способами сразу. В системах Bevy это видно по параметрам: `Query<&T>` читает, `Query<&mut T>` пишет. Времена жизни (lifetime) приходится писать редко. Привыкнуть нужно к двум вещам: хранить id `Entity` вместо ссылки на игрока и вызывать `.clone()` вместо того, чтобы делиться значением. Не копируйте паттерны Rust-серверов на `Arc<Mutex<..>>`: проект избегает их в библиотечных слоях, см. [#566](https://github.com/andreypfau/mcrs/issues/566). Подробнее о владении: [глава Rust Book](https://doc.rust-lang.org/book/ch04-00-understanding-ownership.html).

## Три ошибки, которые встретятся

1. Использование перемещенного значения. Значение передали по значению и использовали снова. Передайте `&value` или вызовите `.clone()`.
2. Функция не принимается как система. У одного из параметров тип, который Bevy не умеет подставлять. Каждый параметр должен быть `Res`, `ResMut`, `Query`, `Commands`, читателем или писателем сообщений либо `Local`.
3. Два параметра одной системы требуют одни и те же данные, и один из них как `&mut`. Планировщик сообщает об этом при построении графа, то есть на старте, а не при компиляции. Объедините запросы или разделите систему.

## Что пока не нужно

Времена жизни (кроме чтения чужих сигнатур), `unsafe`, процедурные макросы и `async`.

## Куда читать

- [The Rust Programming Language](https://doc.rust-lang.org/book/): стоит прочитать главы про владение, enum и `match`, обработку ошибок и трейты.
- [Rust by Example](https://doc.rust-lang.org/rust-by-example/): короткие запускаемые примеры.
- [Rustlings](https://github.com/rust-lang/rustlings): небольшие упражнения.
- [Руководство Cargo](https://doc.rust-lang.org/cargo/guide/): `Cargo.toml` и зависимости.
- [Bevy learn](https://bevy.org/learn/) и [примеры ECS](https://github.com/bevyengine/bevy/tree/main/examples/ecs).
- [Unofficial Bevy Cheat Book](https://bevy-cheatbook.github.io/): может отставать. В mcrs используется Bevy 0.19, где типы называются `Message`, `MessageReader` и `On<E>`, а в старых текстах названия могут быть другими.
- [bevy_ecs на docs.rs](https://docs.rs/bevy_ecs/0.19.1/bevy_ecs/): точные сигнатуры.
