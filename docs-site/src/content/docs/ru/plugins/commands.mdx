На этой странице показано, как плагин добавляет на сервер команду. Вы регистрируете узлы команды, при необходимости требуете для них уровень доступа и пишете обработчик как систему Bevy.

Команды хранятся в типизированном дереве, которое появилось в <Status pr={579} state="works" />. Плагины регистрируют в дереве узлы, а сервер отправляет каждому игроку ту часть дерева, которую разрешает его уровень. Если вы знаете Paper, ближе всего к этому его Commands API с деревом узлов, а аналога `plugin.yml` и `onCommand` здесь нет. Примеры взяты из теста репозитория `commands.rs`, вне репозиторных тестов мы их не запускали.

## Команду регистрирует add_command

`add_command` - метод приложения. Он принимает билдер, который добавляет узлы команды, и обработчик, который команду выполняет.

<Example file="crates/mcrs_minecraft_command_engine/src/app_commands.rs" from="pub trait AppCommandsExt" to="M: 'static;" title="Сигнатура add_command" />

Вызывайте его после того, как в приложение добавлен `CommandPlugin`, и до того, как приложение завершит сборку. Для ванильного набора команд этот плагин уже добавляет `MinecraftServerPlugins`.

Тест ниже собирает команду `echo` с одним целочисленным аргументом:

<Example file="crates/mcrs_minecraft_server/tests/it/commands.rs" from={"#[derive(Clone, Copy)]\nstruct Echo {"} to={"        Ok(Echo { times })\n    }\n}"} title="Тест: узлы команды echo с одним целочисленным аргументом" />

Билдер получает `CommandRegistrar`. Начиная с `NodeId::ROOT`, он добавляет под родительский узел литеральный узел через `literal` или узел аргумента через `arg`. Узел, на котором строка команды заканчивается, вызывает `runs(...)`. Билдер возвращает дескрипторы аргументов, и по ним обработчик потом читает значения.

В том же файле команда регистрируется вызовом `app.add_command(echo_at("echo"), run_echo).unwrap();`. Вызов возвращает `Result`, потому что узел может конфликтовать с деревом. Тогда вы получите ошибку, и из команды не добавится ничего, как показывает тест в конце файла.

## Узел может требовать уровень доступа

Узел запрашивает уровень через `requires(PermissionCheck::Require(level))`. Уровней пять, они упорядочены, и источник проходит проверку, если его уровень не ниже требуемого.

<Example file="crates/mcrs_minecraft_command/src/permission.rs" from={"#[derive(Clone, Copy, Debug, Default, PartialEq, Eq, PartialOrd, Ord, Hash)]\npub enum CommandLevel"} title="CommandLevel" />

Игрок с уровнем ниже требуемого не видит узел в дереве и не может его выполнить. Уровень игрока берется из списка операторов или из уровня сервера по умолчанию.

Строковых узлов прав вроде `myplugin.use` в mcrs нет. Системы прав с группами сегодня тоже нет, и <Status issue={285} /> ее не описывает.

## Обработчик - это система

Обработчик команды `echo` выглядит так:

<Example file="crates/mcrs_minecraft_server/tests/it/commands.rs" from="fn run_echo(" to={"    Ok(times)\n}"} title="Тест: обработчик команды echo" />

Первый параметр обработчика - `In<Call<...>>`, остальные - обычные параметры системы. Обработчик возвращает `CommandResult`, то есть либо число, которое команда сообщает при успехе, либо ошибку. Текст он отправляет через `CommandOutput`, а `Feedback` определяет, кто этот текст услышит: только источник или источник и все операторы.

Обработчик не меняет игрока напрямую, потому что игрок может находиться в другом измерении, до которого обработчик не дотянется. Вместо этого он записывает эффект через `CommandOutput::effect`, а мир применяет эффекты после вызова в том порядке, в каком они записаны. Тип эффекта зарегистрируйте через `add_command_effect`. Именно так `teleport` и `gamemode` меняют игроков в других измерениях. Причины описаны в [docs/command-dimensions.md](https://github.com/andreypfau/mcrs/blob/main/docs/command-dimensions.md) и на странице [Измерения](/docs/ru/plugins/dimensions/).

Команду можно остановить до выполнения. Перед тем как выполнить строку команды, сервер вызывает `CommandEvent` в мире измерения источника. Наблюдатель, то есть функция, которую Bevy вызывает при срабатывании события, может выставить `cancelled`, и тогда команда не выполнится. Это командная часть <Status issue={283} />.

## Что пока не работает

<Aside type="caution" title="WIP">
У <Status issue={285} /> сегодня есть известные ограничения:

- Строить свои команды на ванильных нельзя. Например, `build` и `run` у `kill` объявлены как `pub(crate)`, поэтому плагин не может ни переиспользовать их, ни обернуть.
- Типы аргументов узла берутся из набора аргументов набора команд, то есть `VanillaCommands`. Для типа вне этого набора нужен собственный набор команд.
- Issue просит, чтобы ванильный клиент видел и дополнял команду, которую зарегистрировал тестовый плагин, а игрок с уровнем ниже требуемого не видел ее и не мог выполнить. Влитый PR покрывает дерево и фильтр по уровню. Прежде чем рассчитывать на большее, посмотрите в issue, что осталось.
</Aside>
