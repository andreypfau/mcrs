В этом туториале вы добавите плагин, который считает тики сервера. В mcrs нет ни загрузчика плагинов, ни jar-файлов, об этом рассказывает страница [Это не Paper API](/docs/ru/plugins/not-paper/). Поэтому "установить плагин" здесь значит добавить код на Rust в программу, которая запускает сервер. Плагин лежит в вашей копии репозитория mcrs, рядом с бинарником сервера.

<Aside type="caution" title="WIP">
Сборку плагина в отдельном проекте, где mcrs подключен как git-зависимость, мы не проверяли. Крейты не опубликованы (<Status issue={321} />), а workspace с примерами пока нет (<Status issue={288} />), поэтому на этой странице правится `src/main.rs` внутри клона. Код взят из тестовых файлов репозитория, и вне тестов репозитория эти шаги мы не запускали.
</Aside>

## Восемь терминов этой страницы

Если Rust и Bevy вам в новинку, сначала прочитайте эту таблицу. Полный минимум есть на странице [Rust для Java-разработчика](/docs/ru/plugins/rust-for-java/).

| Слово | Ближайшая идея из Java | Что значит здесь |
|---|---|---|
| plugin (плагин) | `JavaPlugin` с `onEnable` | структура с методом `build`, который добавляет системы и ресурсы в приложение |
| system (система) | задача планировщика или обработчик события | функция, которую Bevy запускает по расписанию, например в `FixedUpdate` |
| resource (ресурс) | поле-одиночка сервера | одно значение на мир, читается через `Res<T>` или `ResMut<T>` |
| observer (наблюдатель) | слушатель события | функция, которая срабатывает при событии; пишется с параметром `On<Event>` |
| query (запрос) | поток (stream) по всем игрокам с фильтром | параметр системы, который обходит сущности с указанными компонентами |
| `&mut` | изменяемая ссылка | заем, который может менять значение; одновременно существует только один |
| `Clone` | `clone()` | копия значения; плагину измерения она нужна, почему - сказано в шаге 2 |
| dimension world (мир измерения) | свой объект `World` на каждое измерение | у каждого измерения свой мир, и плагин строится по одному разу в каждом |

## Шаг 2: напишите плагин

Плагин - это структура, которая реализует `Plugin`. Плагин ниже регистрирует ресурс `Ticks`, в котором хранится число, и одну систему. Система работает в `FixedUpdate` и прибавляет к числу единицу на каждом тике сервера.

<Example file="crates/mcrs_minecraft_server/tests/it/dimension_plugins.rs" from={"#[derive(Resource, Default)]\nstruct Ticks<const ALL: bool>(u32);"} to={"    }\n}"} title="Плагин, который считает тики" />

Код взят из тестового файла репозитория, где плагин считает тики в верхнем мире и в Незере. Чтобы запустить два варианта плагина, тест использует константный обобщенный параметр `ALL`. Читайте код как простой `CountTicks` и не обращайте внимания на `ALL`.

Плагин должен реализовать `Clone`, потому что сервер строит отдельную его копию для каждого мира измерения. В бинарнике сервера уже есть маленький плагин такой формы:

<Example file="src/main.rs" from={"#[derive(Clone)]\nstruct LogInsteadOfPanicPlugin"} to={"    }\n}"} title="Самый маленький Clone-плагин в src/main.rs" />

## Шаг 3: зарегистрируйте его через add_dimension_plugin

Функция `serve()` в `src/main.rs` уже регистрирует один плагин правильным способом. Добавьте свой на следующей строке.

<Example file="src/main.rs" from="fn serve() -> AppExit" to="app.add_dimension_plugin(LogInsteadOfPanicPlugin);" title="Где serve() регистрирует плагин измерения" />

<Aside type="caution" title="add_plugins не доходит до измерения">
Каждое измерение работает как отдельный Bevy `SubApp` со своим `World`. Плагин, добавленный через `app.add_plugins(...)`, попадает в главное приложение и до симуляции измерения не доходит (<Status issue={280} />). Система соберется без ошибок, но ни разу не увидит ни блок, ни моба, ни сущность игрока. Чтобы добавить плагин во все измерения, вызовите `add_dimension_plugin(plugin)`, а чтобы в одно - `add_dimension_plugin_to(key, plugin)`. Вызывайте их до запуска сервера, потому что плагин добавляется до создания измерений. Подробнее об этом на странице [Измерения](/docs/ru/plugins/dimensions/).
</Aside>

Тест показывает оба вызова и то, что сервер из них строит:

<Example file="crates/mcrs_minecraft_server/tests/it/dimension_plugins.rs" from={"#[test]\nfn dimension_plugins_run_in_every_world_or_in_the_world_of_their_key"} to="OVERWORLD, Rate(2)" title="Один плагин в каждом мире и один только в верхнем" />

## Шаг 4: запустите тест, который проверяет счет

Тестовый плагин ничего не печатает. Тест проверяет, что счетчик больше нуля в обоих мирах, через `ticks::<true>(...)` в том же файле. Команда ниже запускает этот тест, и тот же прием использует тест чата (<Status pr={636} state="works" />).

```bash
cargo test -p mcrs_minecraft_server --test it dimension_plugins::
```

Для этой страницы мы команду не запускали. В репозитории нет строки лога для этого плагина, поэтому ожидаемого лога здесь нет. Если он вам нужен, добавьте вызов `tracing::info!` в свою систему.

## Тот же плагин в Paper

<Tabs syncKey="jvm">
<TabItem label="Paper (для сравнения)">
Это Java-код для иллюстрации. Его нет в репозитории, и к mcrs он не относится.

```java
public final class CountTicks extends JavaPlugin {
    private long ticks;

    @Override
    public void onEnable() {
        getServer().getScheduler().runTaskTimer(this, () -> ticks++, 0L, 1L);
    }
}
```
</TabItem>
<TabItem label="mcrs">
Идея та же, а различий три. Плагин mcrs компилируется в программу сервера, тогда как плагин Paper поставляется в jar. Счетчик хранится как ресурс в мире, а в Paper он лежит в поле вашего класса. Задача здесь - система, которую планирует Bevy, и запускается она по одному разу в каждом мире измерения.
</TabItem>
</Tabs>

## Чего плагинам пока не хватает

Четыре вещи, которые могут понадобиться плагину, пока отслеживаются в issue. Это публичные события (<Status issue={283} />), источники чанков (<Status issue={281} />), сохранение (<Status issue={78} />) и измерения во время работы сервера (<Status issue={546} />). Что еще не готово для плагинов, показывает страница [Статус](/docs/ru/start/status/), а почему `add_plugins` не доходит до измерения, объясняет страница [Измерения](/docs/ru/plugins/dimensions/).

Дальше: [Перехват чата](/docs/ru/plugins/chat-event/) берет первое публичное событие, чтобы отменить и переписать строку чата.
