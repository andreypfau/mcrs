Сделаем плагин, который считает тики сервера. Он лежит в копии репозитория mcrs, рядом с бинарником сервера. В mcrs нет загрузчика плагинов и jar-файлов (см. [Это не Paper API](/docs/ru/plugins/not-paper/)), поэтому "установить плагин" значит добавить код на Rust в программу, которая запускает сервер.

<Aside type="caution" title="WIP">
Сборку плагина в отдельном проекте, где mcrs подключен как git-зависимость, мы не проверяли. Крейты не опубликованы (<Status issue={321} />), workspace с примерами пока нет (<Status issue={288} />). Поэтому здесь правится `src/main.rs` внутри клона. Код взят из тестовых файлов репозитория. Вне тестов репозитория эти шаги мы не запускали.
</Aside>

## Слова, которые встретятся дальше

Если Rust и Bevy в новинку, сначала прочитайте эти восемь строк. Полный минимум - на странице [Rust для Java-разработчика](/docs/ru/plugins/rust-for-java/).

| Слово | Ближайшая идея из Java | Что значит здесь |
|---|---|---|
| plugin (плагин) | `JavaPlugin` с `onEnable` | структура с методом `build`, который добавляет системы и ресурсы в приложение |
| system (система) | задача планировщика или обработчик события | функция, которую Bevy запускает по расписанию, например в `FixedUpdate` |
| resource (ресурс) | поле-одиночка сервера | одно значение на мир, читается через `Res<T>` или `ResMut<T>` |
| observer (наблюдатель) | слушатель события | функция, которая срабатывает при событии; пишется как `On<Event>` |
| query (запрос) | поток (stream) по всем игрокам с фильтром | параметр системы, который обходит сущности с указанными компонентами |
| `&mut` | изменяемая ссылка | заем, который может менять значение; одновременно допускается только один |
| `Clone` | `clone()` | копия значения; плагину измерения она нужна, см. ниже |
| dimension world (мир измерения) | свой объект `World` на каждое измерение | у каждого измерения свой мир, и плагин строится в каждом из них |

## Что получится

Ресурс `Ticks` хранит число, а одна система прибавляет к нему единицу на каждом тике сервера. Именно такой плагин есть в тестовом файле репозитория, он считает тики в верхнем мире и в Незере.

## Шаг 1: получите репозиторий

Склонируйте `andreypfau/mcrs`. В разделе [README Quick start](https://github.com/andreypfau/mcrs/blob/main/README.md) есть заметка про тулчейн и команды запуска.

<Aside type="note" title="WIP">
Подробное руководство по установке и запуску появится к альфе. Пока читайте README и технические `.md` файлы репозитория.
</Aside>

## Шаг 2: плагин

Плагин - структура, которая реализует `Plugin`. Этот регистрирует ресурс и систему. Система работает в `FixedUpdate` и прибавляет единицу к счетчику. Чтобы получить два варианта, тест использует константный обобщенный параметр `ALL`. Читайте код как простой `CountTicks` и игнорируйте `ALL`.

<Example file="crates/mcrs_minecraft_server/tests/it/dimension_plugins.rs" from={"#[derive(Resource, Default)]\nstruct Ticks<const ALL: bool>(u32);"} to={"    }\n}"} title="Плагин, который считает тики" />

Плагин должен быть `Clone`: сервер строит отдельную копию для каждого мира измерения, поэтому ему нужно уметь копировать плагин. В бинарнике уже есть маленький плагин такой формы:

<Example file="src/main.rs" from={"#[derive(Clone)]\nstruct LogInsteadOfPanicPlugin"} to={"    }\n}"} title="Самый маленький Clone-плагин в src/main.rs" />

## Шаг 3: зарегистрируйте через add_dimension_plugin

В `serve()` из `src/main.rs` сервер уже регистрирует один плагин правильным способом. Добавьте свой на следующей строке.

<Example file="src/main.rs" from="fn serve() -> AppExit" to="app.add_dimension_plugin(LogInsteadOfPanicPlugin);" title="Где serve() регистрирует плагин измерения" />

<Aside type="caution" title="Ловушка: add_plugins недостаточно">
Каждое измерение работает как отдельный Bevy `SubApp` со своим `World`. Плагин, добавленный через `app.add_plugins(...)`, попадает в главное приложение и не доходит до симуляции измерения (<Status issue={280} />). Система соберется без ошибок, но ни разу не увидит ни блок, ни моба, ни сущность игрока. Для всех измерений используйте `add_dimension_plugin(plugin)`, для одного - `add_dimension_plugin_to(key, plugin)`. Плагин добавляется до создания измерений, поэтому вызывайте функцию до запуска сервера. Подробнее - на странице [Измерения](/docs/ru/plugins/dimensions/).
</Aside>

Тест показывает оба вызова и то, что сервер из них строит:

## Шаг 4: посмотрите счет

Тестовый плагин ничего не печатает: он проверяет, что счетчик больше нуля в обоих мирах (`ticks::<true>(...)` в том же файле). Команда ниже запускает этот тест. Тот же прием использует тест чата (<Status pr={636} state="works" />).

```bash
cargo test -p mcrs_minecraft_server --test it dimension_plugins::
```

Эту команду мы для страницы не запускали. В репозитории нет строки лога для этого плагина, поэтому ожидаемого лога здесь нет. Если он нужен, добавьте вызов `tracing::info!` в свою систему.

## То же самое в Paper

<TabItem label="Paper (для сравнения)">
Это Java-код для иллюстрации. Его нет в репозитории, и к mcrs он не относится.

```java
public final class CountTicks extends JavaPlugin {
    private long ticks;

    @Override
    public void onEnable() {
        getServer().getScheduler().runTaskTimer(this, () -> ticks++, 0L, 1L);
    }
}
```
</TabItem>
<TabItem label="mcrs">
Идея та же, но различий три. Плагин входит в программу сервера, а не лежит в jar. Счетчик - ресурс в мире, а не поле класса. Задача - система, которую планирует Bevy, и она запускается по одному разу в каждом мире измерения.
</TabItem>
</Tabs>
