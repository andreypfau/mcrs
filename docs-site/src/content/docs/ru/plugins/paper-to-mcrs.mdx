Страница для поиска: найдите знакомое понятие из Paper, Velocity или Minestom и посмотрите, что ближе всего к нему в mcrs. Если слова "сущность" и "система" незнакомы, прочтите [От объектов к данным](/docs/ru/plugins/mental-model/).

<Aside type="caution" title="Аналог, не замена">
Каждая строка - аналогия. Bukkit-подобного API в mcrs нет, см. [Это не Paper API](/docs/ru/plugins/not-paper/). Строка со статусом wip описывает запланированную возможность: она есть в issue, а в коде ее еще нет. У строки со статусом undecided нет ни issue, ни решения.
</Aside>

## Жизненный цикл

| JVM | mcrs | Состояние | Заметки |
|---|---|---|---|
| `JavaPlugin`, `onEnable` | `impl Plugin for X` с `fn build(&self, app: &mut App)` | <Status issue={279} state="works" /> | Как в Minestom: свой `main` пишете вы ([src/main.rs](https://github.com/andreypfau/mcrs/blob/main/src/main.rs)). Нет `plugin.yml`, нет отдельного jar |
| `onDisable` | Хука нет. Остановка идет через сообщение `ShutdownRequest` | <Status state="partial" doc="crates/mcrs_minecraft_engine_server/src/shutdown.rs" /> | Запрос отправляет код, который встраивает сервер, обработчик сигналов не устанавливается |
| `depend:` и `softdepend:` | Группа плагинов: если плагину нужен другой, он падает в `build` и называет недостающий | <Status issue={279} state="works" /> | См. `MinecraftServerPlugins` в [lib.rs](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server/src/lib.rs) |
| Отключить встроенную часть | `server.disable::<SomePlugin>()` на группе плагинов | <Status issue={282} state="works" /> | Используется в [`main.rs`](https://github.com/andreypfau/mcrs/blob/main/src/main.rs), чтобы выключить мозг мобов |
| `/reload`, PlugMan | Нет. Код не перезагружается | <Status issue={316} state="wip" /> | Планируется только перезагрузка датапаков |
| NMS, CraftBukkit | Любой публичный крейт библиотечных слоев | <Status issue={437} state="declined" /> | Фасада между кодом и движком нет. Это одновременно NMS и API |
| Статический `Bukkit.getServer()` | Нет. `Res<T>`, `Query<..>` и `Commands` берутся как параметры системы | <Status issue={437} state="declined" /> | Статический доступ отклонили |
| Зависимость от `paper-api` | Git-зависимость от крейтов mcrs | <Status issue={321} state="undecided" /> | Одна версия игры за раз, без обратной совместимости (<Status issue={412} state="declined" />) |

## События

| JVM | mcrs | Состояние | Заметки |
|---|---|---|---|
| `Listener`, `@EventHandler` | Наблюдатель `app.add_observer(f)` с `f: fn(On<Event>)` или `MessageReader<M>` для буфера сообщений | <Status issue={283} state="partial" /> | Публичные события есть только для чата. Наблюдатели пакетов есть как `Received<P>` |
| `setCancelled(true)` | Поле `cancelled` события, которое меняет наблюдатель с параметром `mut` | <Status pr={636} state="partial" /> | Только `PlayerChatEvent`. Общий механизм с откатом предсказания клиента - это <Status issue={283} state="partial" /> |
| `AsyncChatEvent` | `PlayerChatEvent { player, text, cancelled }` | <Status pr={636} state="works" /> | `text` - компонент `Text`, а не `String`. Событие срабатывает до рассылки |
| `EventPriority` | Порядок систем: `.before()`, `.after()`, `SystemSet`, например `TickSet` | <Status issue={323} state="works" /> | У наблюдателей приоритета нет. Неупорядоченный конфликт ломает тест |
| `PlayerJoinEvent`, `PlayerQuitEvent` | Внутренние сообщения шины `InboundPlayerSpawn` и `InboundPlayerDespawn` | <Status issue={283} state="partial" /> | Публичного события пока нет, вход и выход запланированы |
| `BlockBreakEvent`, `BlockPlaceEvent` | Внутреннее сообщение `BlockActionRequest` | <Status issue={283} state="partial" /> | Публичные отменяемые события запланированы |
| `ProtocolLib`, слушатели пакетов | `On<Received<P>>` над типизированными игровыми пакетами | <Status state="partial" /> | Типизирована примерно половина пакетов, см. README. Единый путь типизированного приема: <Status issue={57} state="partial" /> |
| Дерево `EventNode` в Minestom | Дерева событий нет, есть только наблюдатели и расписания Bevy | <Status state="undecided" /> | Issue нет, этот паттерн не копируйте |

## Планировщик

| JVM | mcrs | Состояние | Заметки |
|---|---|---|---|
| `runTaskTimer` | Система в `FixedUpdate`, по умолчанию 20 тиков в секунду (`DEFAULT_TPS`) | <Status state="works" doc="crates/mcrs_minecraft_engine_server/src/runner.rs" /> | Состояние хранится в ресурсе или `Local<T>`. Планирует Bevy, собственного планировщика в mcrs нет |
| `runTaskLater` | Счетчик или таймер в ресурсе или компоненте, либо `Res<Time<Fixed>>` | <Status state="works" /> | Вручную, готовых хелперов нет |

| `runTaskAsynchronously` | Пулы задач Bevy есть, но документированного паттерна для плагинов нет | <Status state="partial" /> | Issue нет. Параллельность обеспечивает планировщик |
