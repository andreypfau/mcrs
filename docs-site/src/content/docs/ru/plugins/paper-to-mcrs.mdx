Эта страница - справочная таблица для тех, кто знает Paper, Velocity или Minestom. Найдите знакомое название, и строка покажет, что ближе всего к нему в mcrs и в каком это состоянии сегодня. Если слова "сущность" и "система" вам незнакомы, сначала прочтите [От объектов к данным](/docs/ru/plugins/mental-model/).

<Aside type="caution" title="Каждая строка - аналогия">
Ни одна строка не дает готовой замены, потому что Bukkit-подобного API в mcrs нет, как объясняет страница [Это не Paper API](/docs/ru/plugins/not-paper/). Строка со статусом wip - это запланированная возможность, на которую есть issue, но еще нет кода. У строки со статусом undecided нет ни issue, ни решения.
</Aside>

## Жизненный цикл

| JVM | mcrs | Состояние | Заметки |
|---|---|---|---|
| `JavaPlugin`, `onEnable` | `impl Plugin for X` с `fn build(&self, app: &mut App)` | <Status issue={279} /> | Как и в Minestom, свой `main` пишете вы, см. [src/main.rs](https://github.com/andreypfau/mcrs/blob/main/src/main.rs). Ни `plugin.yml`, ни отдельного jar нет |
| `onDisable` | Хука нет. Остановка идет через сообщение `ShutdownRequest` | <Status state="partial" doc="crates/mcrs_minecraft_engine_server/src/shutdown.rs" /> | Запрос отправляет код, который встраивает сервер, либо этот код вызывает `request_shutdown` у `ServerThread`. Плагин не ставит обработчик сигналов |
| `depend:` и `softdepend:` | Группа плагинов: если плагину нужен другой, он падает в `build` и называет недостающий | <Status issue={279} /> | См. `MinecraftServerPlugins` в [lib.rs](https://github.com/andreypfau/mcrs/blob/main/crates/mcrs_minecraft_server/src/lib.rs) |
| Отключить встроенную часть | `server.disable::<SomePlugin>()` на группе плагинов | <Status issue={282} /> | Используется в [`main.rs`](https://github.com/andreypfau/mcrs/blob/main/src/main.rs), чтобы выключить мозг мобов |
| `/reload`, PlugMan | Нет. Код не перезагружается | <Status issue={316} /> | Планируется только перезагрузка датапаков |
| NMS, CraftBukkit | Любой публичный крейт библиотечных слоев | <Status issue={437} /> | Фасада между вашим кодом и движком нет, поэтому эти крейты - одновременно NMS и API |
| Статический `Bukkit.getServer()` | Нет. `Res<T>`, `Query<..>` и `Commands` берутся как параметры системы | <Status issue={437} /> | Статический доступ отклонили |
| Зависимость от `paper-api` | Git-зависимость от крейтов mcrs | <Status issue={321} /> | Одна версия игры за раз, без обратной совместимости (<Status issue={412} />) |

## События

| JVM | mcrs | Состояние | Заметки |
|---|---|---|---|
| `Listener`, `@EventHandler` | Наблюдатель `app.add_observer(f)` с `f: fn(On<Event>)` или `MessageReader<M>` для буфера сообщений | <Status issue={283} /> | Точка расширения зависит от области: у чата и команд есть `cancelled`, у инвентаря `RequestCheck`, у урона набор фильтрации. Наблюдатели пакетов используют `Received<P>` |
| `setCancelled(true)` | Поле `cancelled` события, которое меняет наблюдатель с параметром `mut` | <Status pr={636} state="partial" /> | Только `PlayerChatEvent` и `CommandEvent`. Общий механизм с откатом предсказания клиента - это <Status issue={283} /> |
| `AsyncChatEvent` | `PlayerChatEvent { player, text, cancelled }` | <Status pr={636} state="works" /> | `text` - компонент `Text`, а не `String`. Событие срабатывает до рассылки |
| `EventPriority` | Порядок систем: `.before()`, `.after()`, `SystemSet`, например `TickSet` | <Status issue={323} /> | У наблюдателей приоритета нет. Неупорядоченный конфликт ломает тест |
| `PlayerJoinEvent`, `PlayerQuitEvent` | Внутренние сообщения шины `InboundPlayerSpawn` и `InboundPlayerDespawn` | <Status issue={283} /> | Публичного события пока нет. Публичные события входа и выхода запланированы |
| `BlockBreakEvent`, `BlockPlaceEvent` | Публичное сообщение `UseItemOnRequest` для установки и публичный набор `BlockBreakSet`, после которого ставится своя система | <Status issue={283} /> | Отменяемых событий пока нет. Запрос на ломание внутренний, а отклонить установку можно, только заменив `VanillaBlockPlacePlugin`. Подробнее на странице [Встроиться в установку, ломание и дроп блоков](/docs/ru/plugins/blocks/) |
| `InventoryClickEvent`, `setCancelled(true)` | Наблюдатель `RequestCheck`, который вызывает `deny(Denial { source, code })`, или `Gate` в `SlotPolicy` держателя | <Status pr={846} state="works" /> | Клик приходит как запрос к инвентарю. В отказе указан источник запросов плагина. Клик по кнопке меню приходит как `EntryPressed`. Подробнее на странице [Инвентарь](/docs/ru/plugins/inventory/) |
| `EntityDamageEvent` | Система в `DamageSet::Filter` меняет или убирает значения `DamageRequest` в `PendingHits` | <Status pr={1078} state="works" /> | Работает для мобов и игроков. `Damaged` сообщает о принятом ударе; подробности на странице [Чтение данных игрока](/docs/ru/plugins/players/#здоровье-урон-и-смерть) |
| `PlayerDeathEvent` | Читайте `Died`; замените `VanillaDeathDropsPlugin` или `VanillaDeathMessagesPlugin` | <Status pr={1084} state="works" /> | Свой текст смерти пишется как `DeathMessage` в `PlayerDeathSet::Describe`. Дроп и `keep_inventory` разобраны на странице [Инвентарь](/docs/ru/plugins/inventory/#инвентарь-при-смерти) |
| `PlayerRespawnEvent` | Пишите `RespawnRequest { player, dimension, transform }` в мире игрока | <Status pr={1082} state="works" /> | Для своей точки возрождения замените `VanillaRespawnPlugin`; это запрос, а не отменяемое событие |
| `Bukkit.createInventory`, `openInventory` | Значение `MenuLayout`, полученное из `MenuLayout::of(MenuType::Generic9x3)` как `Some(layout)`, поверх сущности-держателя со `Slots`, открытое через `open_titled_menu` из `MenuCommandsExt` | <Status pr={977} state="works" /> | Записи-кнопки из `MenuButtons` не двигают стек и пишут `EntryPressed`. `close_menu` заменяет `closeInventory`. Клиент mcrs рисует восемь типовых экранов контейнеров и принимает в них клики (<Status issue={130} />). Подробнее на странице [Инвентарь](/docs/ru/plugins/inventory/) |
| `ProtocolLib`, слушатели пакетов | `On<Received<P>>` над типизированными игровыми пакетами | <Status state="partial" /> | Типизирована примерно половина пакетов, см. README. Единый путь типизированного приема: <Status issue={57} /> |
| Дерево `EventNode` в Minestom | Дерева событий нет, есть только наблюдатели и расписания Bevy | <Status state="undecided" /> | Issue нет. Этот паттерн не копируйте |
