В Paper `Player` - объект с методами. В mcrs игрок - сущность внутри мира измерения, а его состояние - набор компонентов. Объекта `Player`, за который можно держаться, нет, вместо него пишут запрос. Страница намеренно короткая: набор компонентов растет вместе с проектом. Примеры взяты из файлов репозитория, вне репозиторных тестов мы их не запускали.

## Запрос игроков

У сущности игрока есть компонент-маркер `Player`. Система в мире измерения видит только игроков этого измерения (см. [Измерения](/docs/ru/plugins/dimensions/)). Тестовое окружение находит игрока таким же запросом:

## Три разных идентификатора

У одного игрока три идентификатора, и они не взаимозаменяемы.

| Идентификатор | Где | Что это |
|---|---|---|
| `GameProfile::id` | компонент игрока | UUID профиля, как в Paper |
| `PlayerSession` | компонент `Owner` игрока в мире измерения, а также на хосте | имя одного соединения. Хост не выдает одно значение дважды, а смена измерения его сохраняет |
| `Entity` | сущность игрока внутри одного мира измерения | идентификатор Bevy, который существует только в одном мире. У хоста для того же игрока есть еще якорная сущность, и это другая сущность |

<Example file="crates/mcrs_minecraft_engine_world/src/session/sessions.rs" from={"#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]\npub struct PlayerSession"} title="PlayerSession" />

Сессия нужна, чтобы адресовать игрока между мирами и отправлять пакеты. UUID используйте для всего, что должно пережить переподключение.

<Aside type="caution" title="WIP: идентификатор в сети">
Идентификатор сущности, который получает клиент, сегодня равен индексу `Entity` Bevy в мире измерения. У этого два недостатка, по <Status issue={158} />. Во-первых, Bevy может отдать освобожденный индекс новой сущности, пока клиент еще отслеживает старую, а ванильный сервер не использует идентификатор повторно, пока работает. Во-вторых, два мира измерений выделяют индексы независимо, поэтому идентификаторы сталкиваются, как только одно соединение видит сущности нескольких владельцев. В issue запланирован компонент `NetId` для каждой сетевой сущности: идентификаторы выдаются в аренду каждому миру, не используются повторно и сохраняются, когда сущность передают другому узлу. Пока issue не закрыт, не храните сетевой идентификатор сущности и не рассчитывайте, что он останется прежним.
</Aside>

## Изменение игрока

Не меняйте другого игрока из системы, которая работает в другом мире. Внутри мира игрока его компоненты можно вставлять и править. Между мирами изменение - это сообщение или эффект. Ванильные команды `gamemode` и `teleport` делают так через эффекты команд, см. [Добавить команду](/docs/ru/plugins/commands/).

## Отправка сообщения игроку

Метода `player.sendMessage()` нет. Низкоуровневый способ - записать пакет в сессию. Плагин чата так и делает для игрока, который скрыл чат:

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" from="info.is_some_and(|info| info.chat_mode == ChatMode::Hidden)" title="Записать пакет системного чата в сессию игрока" />

Более удобного слоя для этого пока нет. Issue о нем мы не знаем, поэтому ничего не обещаем.
