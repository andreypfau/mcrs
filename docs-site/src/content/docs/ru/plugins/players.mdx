Эта страница показывает, как плагин находит игроков, читает их данные, различает их идентификаторы и меняет их состояние. В Paper `Player` - объект с методами. В mcrs игрок - сущность внутри мира измерения, а его состояние хранится в наборе компонентов. Поэтому там, где код для Paper держал бы объект, вы пишете запрос.

Страница короткая, потому что набор компонентов растет вместе с проектом. Примеры взяты из файлов репозитория, и вне тестов репозитория мы их не запускали.

## Игроков находит запрос

У каждой сущности игрока есть компонент-маркер `Player`. Система в мире измерения видит игроков только этого измерения, об этом рассказывает страница [Измерения](/docs/ru/plugins/dimensions/). Тестовое окружение находит игрока таким же запросом:

## У одного игрока три идентификатора

Подставить один из них вместо другого нельзя.

| Идентификатор | Где | Что это |
|---|---|---|
| `GameProfile::id` | компонент игрока | UUID профиля, как в Paper |
| `PlayerSession` | компонент `Owner` игрока в мире измерения, а также на хосте | имя одного соединения. Хост не выдает одно значение дважды, а при смене измерения оно сохраняется |
| `Entity` | сущность игрока внутри одного мира измерения | идентификатор Bevy, который существует только в одном мире. У хоста для того же игрока есть еще якорная сущность, и это другая сущность |

<Example file="crates/mcrs_minecraft_engine_world/src/session/sessions.rs" from={"#[derive(Debug, Clone, Copy, PartialEq, Eq, Hash)]\npub struct PlayerSession"} title="PlayerSession" />

По сессии адресуйте игрока между мирами и отправляйте ему пакеты. UUID берите для всего, что должно пережить переподключение.

<Aside type="caution" title="WIP: идентификатор в сети">
Идентификатор сущности, который получает клиент, сегодня равен индексу `Entity` Bevy в мире измерения. У такой схемы два недостатка.[^158] Bevy может отдать освобожденный индекс новой сущности, пока клиент еще отслеживает старую, а ванильный сервер не использует идентификатор повторно, пока работает. Кроме того, два мира измерений выделяют индексы независимо, поэтому идентификаторы сталкиваются, как только одно соединение видит сущности нескольких владельцев. Запланирован компонент `NetId` для каждой сетевой сущности. Его идентификаторы выдаются в аренду каждому миру, не используются повторно и сохраняются, когда сущность передают другому узлу.[^158] Пока этот план не выполнен, не храните сетевой идентификатор сущности и не рассчитывайте, что он останется прежним.
</Aside>

## Игрока меняют внутри его мира

Внутри мира игрока его компоненты можно вставлять и править. Не меняйте игрока из системы, которая работает в другом мире. Изменение, которое пересекает границу миров, передается сообщением или эффектом. Ванильные команды `gamemode` и `teleport` делают это через эффекты команд, см. [Добавить команду](/docs/ru/plugins/commands/).

## Отправка сообщения игроку

Метода `player.sendMessage()` в mcrs нет. Низкоуровневый способ - записать пакет в сессию. Плагин чата так и поступает с игроком, который скрыл чат:

<Example file="crates/mcrs_minecraft_chat_server/src/chat_plugin.rs" from="info.is_some_and(|info| info.chat_mode == ChatMode::Hidden)" title="Записать пакет системного чата в сессию игрока" />

Более удобного слоя для этого пока нет. Issue о нем мы не знаем, поэтому ничего не обещаем.

Сохранение данных игрока тоже не готово.[^78] Состояние сохранения показывает страница [Статус](/docs/ru/start/status/).
