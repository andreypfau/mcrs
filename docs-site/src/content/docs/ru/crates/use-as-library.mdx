Крейт mcrs можно подключить к своему Rust-проекту уже сегодня: нужны git-зависимость, закрепленный коммит и nightly-компилятор. На crates.io крейтов нет. При этой проверке документации путь не тестировался в чистом внешнем проекте, поэтому настройка ниже остается WIP с известными ограничениями.

<Aside type="caution" title="WIP">
Публикация крейтов протокола, сети и игровых данных ждет решения.[^321] Вопрос в том, нужны ли публикация и stable Rust вообще, пока проект идет за одним снапшотом игры за раз. В `examples/` лежат шесть примеров, и у каждого есть тест дерева зависимостей.[^288] Примеры минимального сервера, лобби и арены запланированы.[^287]
</Aside>

## 1. Добавьте git-зависимость с закрепленным rev

```toml
[dependencies]
mcrs_minecraft_protocol = { git = "https://github.com/andreypfau/mcrs", rev = "51d45c26ae772bd71fb1e02caae8cab2e5ad4495", default-features = false }
```

Cargo находит крейт по имени внутри репозитория, поэтому один и тот же адрес в `git` подходит для любого крейта mcrs. Для всех них в дереве зависимостей указывайте один `rev`.

Не пишите `branch = "main"`. Ветка `main` переходит на следующий снапшот игры, и крейты меняются вместе с ней, так что сборка может сломаться, хотя у себя вы ничего не трогали. В репозитории 11 тегов, а точно закрепить версию можно хешем коммита.

## 2. Поставьте nightly-компилятор

Репозиторий закрепляет `nightly-2026-09-02` в [`rust-toolchain.toml`](https://github.com/andreypfau/mcrs/blob/main/rust-toolchain.toml). На git-зависимость это закрепление не распространяется. Поставьте nightly сами и закрепите его в своем проекте, лучше с той же датой.

Поддержка stable-компилятора в нижних слоях здесь не проверена. Она входит в вопрос о публикации крейтов, поэтому для этого пути используйте закрепленный nightly.[^321]

## 3. Оставьте Bevy снаружи

Крейты разложены по слоям, от сетевого протокола в слое 1 до приложений в слое 7. Крейты протокола, данных и правил должны работать без Bevy. Для `mcrs_minecraft_protocol` параметр `default-features = false` в строке зависимости выше оставляет необязательную интеграцию с Bevy выключенной.

CI проверяет {fact('crates_no_bevy')} имени пакетов командой `cargo check --no-default-features`. Список лежит в `NO_BEVY_PACKAGES` в [`xtask/src/checks.rs`](https://github.com/andreypfau/mcrs/blob/main/xtask/src/checks.rs), а в [карте крейтов](/docs/ru/crates/overview/) отмечен каждый из этих пакетов.

Слой 4 использует Bevy, чтобы запускать правила по расписанию. В верхних слоях есть и крейты поведения без Bevy, и плагины Bevy, поэтому проверяйте манифест крейта. Ниже движка `mcrs_minecraft_assets` все еще требует Bevy даже с отключенными feature-флагами по умолчанию.

## 4. Проверьте, что подтянулось

Запустите в своем проекте эту команду, и она покажет, попали ли Bevy или tokio в дерево зависимостей:

```bash
cargo tree -e normal --prefix none | grep -i -E "bevy|tokio" || echo "no bevy, no tokio"
```

Если Bevy появился из-за крейта из списка "без Bevy", это баг в mcrs, заведите issue. Та же команда покажет и tokio, который ниже слоя 2 тоже необязательная feature.

## Что пока не работает

Не все крейты готовы к публикации и упаковке. Если крейт при сборке читает файлы вне своей папки, их тоже нужно включить в пакет. Известные случаи - `crates/mcrs_minecraft_core/src/version.rs`, который читает `assets/minecraft/version.json`, и интеграция с Bevy в `crates/mcrs_minecraft_network/src/server.rs`, которая встраивает `assets/mcrs/server-icon.png`. Git-зависимость работает, потому что Cargo клонирует весь репозиторий.[^321]

Некоторые публичные API протокола и сети все еще возвращают ошибки `anyhow`. У фрейминга уже есть тип `FrameError` с методом `is_incomplete()`, а `PacketDecoder::try_next_packet()` возвращает `Ok(None)`, когда нужны дополнительные байты. Вызывающий код может отличить неполный фрейм от некорректного без сравнения текста ошибок.

Программы в [`examples/`](https://github.com/andreypfau/mcrs/tree/main/examples) входят в workspace и берут зависимости через `workspace = true`, поэтому им нужен workspace репозитория. Самый маленький туториал - [Разбор SNBT в своем проекте](/docs/ru/crates/hello-nbt/). Его настройка для внешнего проекта при этой проверке документации тоже не тестировалась заново.

Стабильного API нет. Типы меняются с каждым снапшотом игры, поэтому закрепите rev и читайте изменения, прежде чем его сдвигать.

## Если вы пришли с JVM

У mcrs нет артефакта на Maven Central и нет jar-плагина, который кладут в папку. Решения о загрузчике плагинов тоже пока нет, будь то jar, wasm или скрипты. Проект отклонил только фасад и Bukkit-подобный API, а о загрузчике в этом решении ничего нет.[^437] Сегодня ваш собственный код - это Rust-плагин для Bevy, который вы компилируете вместе с сервером, подробнее об этом на странице [Это не Paper API](/docs/ru/plugins/not-paper/).
