Девять крейтов нижней части графа есть на crates.io и собираются на stable Rust. Список есть в разделе [Что пока не работает](#что-пока-не-работает). Любой другой крейт mcrs подключайте git-зависимостью с закрепленным коммитом и nightly-компилятором. Вне репозитория на чистой машине путь через git пока никто не проверял, так что читайте страницу как план с известными ограничениями.

<Aside type="caution" title="WIP">
Публикация крейтов протокола, сети и игровых данных ждет, пока не уберут блокеры, описанные ниже.[^321] Примеры использования библиотеки, каждый с тестом своего дерева зависимостей, запланированы.[^287][^288]
</Aside>

## 1. Добавьте git-зависимость с закрепленным rev

```toml
[dependencies]
mcrs_minecraft_protocol = { git = "https://github.com/andreypfau/mcrs", rev = "51d45c26ae772bd71fb1e02caae8cab2e5ad4495", default-features = false }
```

Cargo находит крейт по имени внутри репозитория, поэтому один и тот же адрес в `git` подходит для любого крейта mcrs. Для всех них в дереве зависимостей указывайте один `rev`.

Не пишите `branch = "main"`. Ветка `main` переходит на следующий снапшот игры, и крейты меняются вместе с ней, так что сборка может сломаться, хотя у себя вы ничего не трогали. В репозитории 11 тегов, а точно закрепить версию можно хешем коммита.

## 2. Поставьте nightly-компилятор

Репозиторий закрепляет `nightly-2026-09-02` в [`rust-toolchain.toml`](https://github.com/andreypfau/mcrs/blob/main/rust-toolchain.toml). Cargo читает этот файл только в каталоге, где его запустили, поэтому на git-зависимость закрепление не распространяется. Поставьте nightly сами и закрепите его в своем проекте, лучше с той же датой.

Девять крейтов с crates.io собираются на stable. Заявленная цель - чтобы на stable собирались и крейты протокола, сети и игровых данных. Сегодня собираются не все.[^321]

## 3. Оставьте Bevy снаружи

Крейты разложены по слоям, от сетевого протокола в слое 1 до приложений в слое 7. Ниже слоя 4 Bevy - необязательная feature, поэтому `default-features = false` в строке зависимости выше не пускает его в вашу сборку.

CI проверяет {fact('crates_no_bevy')} имен пакетов командой `cargo check --no-default-features`. Список лежит в `NO_BEVY_PACKAGES` в [`xtask/src/checks.rs`](https://github.com/andreypfau/mcrs/blob/main/xtask/src/checks.rs), а в [карте крейтов](/docs/ru/crates/overview/) отмечен каждый из этих пакетов.

Слою 4 и выше Bevy нужен. В нижних слоях известно одно исключение, `mcrs_minecraft_assets`: по README ему нужен Bevy, даже если default features отключены.

## 4. Проверьте, что подтянулось

Запустите в своем проекте эту команду, и она покажет, попали ли Bevy или tokio в дерево зависимостей:

```bash
cargo tree -e normal --prefix none | grep -i -E "bevy|tokio" || echo "no bevy, no tokio"
```

Если Bevy появился из-за крейта из списка "без Bevy", это баг в mcrs, заведите issue. Та же команда покажет и tokio, который ниже слоя 2 тоже необязательная feature.

## Что пока не работает

На crates.io есть только крейты нижней части графа: `mcrs_minecraft_resource`, `mcrs_voxel`, `mcrs_minecraft_wire_macros`, `mcrs_minecraft_wire`, `mcrs_minecraft_nbt`, `mcrs_minecraft_snbt`, `mcrs_minecraft_core`, `mcrs_minecraft_profile` и `mcrs_minecraft_text`. Они собираются на stable Rust. Остальные крейты подключайте git-зависимостью.

`cargo package` падает на крейте, который при сборке читает файлы вне своей папки. Известный случай: `crates/mcrs_minecraft_client_world/src/registries.rs` встраивает `assets/mcrs/reports/datapack.json`. Git-зависимость работает, потому что Cargo клонирует весь репозиторий.[^321]

Вторым блокером то же issue называет типы ошибок. Публичный API крейтов протокола и сети в нескольких местах возвращает ошибки `anyhow`, поэтому вызывающий код не отличит неполный фрейм от сломанного, если не сравнивает текст.

Примера проекта, который можно скопировать, нет. Первый маленький пример - [разбор SNBT в своем проекте](/docs/ru/crates/hello-nbt/), и он сам не проверен вне workspace.

Стабильного API нет. Типы меняются с каждым снапшотом игры, поэтому закрепите rev и читайте изменения, прежде чем его сдвигать.

## Если вы пришли с JVM

У mcrs нет артефакта на Maven Central и нет jar-плагина, который кладут в папку. Решения о загрузчике плагинов тоже пока нет, будь то jar, wasm или скрипты. Проект отклонил только фасад и Bukkit-подобный API, а о загрузчике в этом решении ничего нет.[^437] Сегодня ваш собственный код - это Rust-плагин для Bevy, который вы компилируете вместе с сервером, подробнее об этом на странице [Это не Paper API](/docs/ru/plugins/not-paper/).
