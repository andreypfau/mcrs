Крейт mcrs можно подключить к своему Rust-проекту уже сегодня, через git-зависимость. С crates.io его не взять, а этот путь вне репозитория на чистой машине пока никто не проверял. Поэтому читайте страницу как план и список известных ограничений, а не как проверенное руководство.

## 1. Git-зависимость с rev

```toml
[dependencies]
mcrs_minecraft_protocol = { git = "https://github.com/andreypfau/mcrs", rev = "51d45c26ae772bd71fb1e02caae8cab2e5ad4495", default-features = false }
```

Cargo находит крейт по имени внутри репозитория. Для всех крейтов mcrs в дереве зависимостей используйте один `rev`. `branch = "main"` не подходит: `main` переходит на следующий снапшот игры, и крейты меняются вместе с ним. В репозитории 11 тегов, а точно закрепить версию можно хешем коммита.

## 2. Nightly Rust

Репозиторий закрепляет `nightly-2026-09-02` в [`rust-toolchain.toml`](https://github.com/andreypfau/mcrs/blob/main/rust-toolchain.toml). Cargo читает этот файл только в каталоге, где его запустили, поэтому за git-зависимостью он не следует. Поставьте nightly сами и закрепите его в своем проекте, лучше ту же дату. Собираются ли нижние слои еще и на stable, не проверено. Заявленная цель <Status issue={321} state="undecided" /> - чтобы крейты протокола, сети и игровых данных собирались на stable. Значит, сегодня собираются не все.

## 3. Оставьте Bevy снаружи

Ниже слоя 4 Bevy - необязательная feature, поэтому `default-features = false` не пускает его в сборку. CI проверяет 100 имен пакетов через `cargo check --no-default-features`. Список лежит в `NO_BEVY_PACKAGES` в [`xtask/src/checks.rs`](https://github.com/andreypfau/mcrs/blob/main/xtask/src/checks.rs), а в [карте крейтов](/docs/ru/crates/overview/) отмечен каждый из этих пакетов.

Слою 4 и выше нужен Bevy. Среди нижних слоев известное исключение - `mcrs_minecraft_assets`: по README ему нужен Bevy, даже если default features отключены.

## 4. Проверьте, что подтянулось

```bash
cargo tree -e normal --prefix none | grep -i -E "bevy|tokio" || echo "no bevy, no tokio"
```

Если Bevy появился в крейте из списка "без Bevy", это баг в mcrs: заведите issue. Ниже слоя 2 tokio тоже необязательная feature, и та же проверка его покажет.

## Что не работает

- `cargo package` падает для крейтов, которые при сборке читают файлы вне своей папки. Известны два случая: `crates/mcrs_minecraft_core/src/version.rs` читает `assets/minecraft/version.json`, а `crates/mcrs_minecraft_game_rule/src/lib.rs` - файл из `assets/mcrs/`. Git-зависимость работает, потому что клонируется весь репозиторий. Из-за этого публикация заблокирована (<Status issue={321} state="undecided" />).
- Публичный API крейтов протокола и сети в нескольких местах возвращает ошибки `anyhow`, поэтому вызывающий код не отличит неполный фрейм от сломанного, не сопоставляя текст. То же issue называет это вторым блокером.
- Примера проекта, который можно скопировать, нет. Первый маленький пример - [разбор SNBT](/docs/ru/crates/hello-nbt/), и он сам не проверен вне workspace.
- Типы меняются с каждым снапшотом игры, обещаний стабильного API нет. Закрепите rev и читайте изменения, прежде чем его сдвигать.

## Если вы пришли с JVM

Артефакта mcrs на Maven Central нет, и jar-плагина, который можно бросить в папку, тоже. Решения о загрузчике плагинов (jar, wasm или скрипты) пока нет: <Status issue={437} state="declined" /> отклоняет только фасад и Bukkit-подобный API, а о загрузчике ничего не говорит. Собственный код сегодня - это Rust-плагин для Bevy, который компилируется вместе с сервером. См. [Это не Paper API](/docs/ru/plugins/not-paper/).
