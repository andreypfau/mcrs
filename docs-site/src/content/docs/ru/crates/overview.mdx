## Как читать таблицу

Слои взяты из [README](https://github.com/andreypfau/mcrs/blob/main/README.md#layers). Каждый слой должен зависеть только от нижних, поэтому можно взять префикс слоев и не платить за то, что выше. Несколько крейтов пока этому не следуют: крейты протокола и сети все еще обращаются к игровым данным. CI проверяет только часть этого правила: крейты wire и сети не должны линковать игровые данные.

Слой крейта нигде не хранится в коде. Его назначили вручную по таблице из README и описанию крейта, так что это ориентир, а не проверенный факт.

| Столбец | Откуда берется |
|---|---|
| Описание | `description` из `Cargo.toml` крейта. У пяти крейтов описания не было или было только их имя, поэтому для них описание написано по исходникам |
| Без Bevy | `NO_BEVY_PACKAGES` в [`checks.rs`](https://github.com/andreypfau/mcrs/blob/main/xtask/src/checks.rs). CI запускает для этих крейтов `cargo check --no-default-features` и падает, если какому-то нужен Bevy |
| no_std | `NO_STD_PACKAGES`, в CI собираются без `std` |
| wasm32 | `WASM32_PACKAGES`, в CI собираются под цель `wasm32` |

В списке "без Bevy" 100 имен. Шесть из них - инструменты из `tools/`, поэтому среди 122 крейтов из `crates/` таких 94. В списке no_std 9 крейтов, в списке wasm32 - 11. Прочерк значит "нет в списке CI", а не "не работает".

## Что брать для задачи

Ничего из этого не опубликовано на crates.io, поэтому во всех случаях ниже нужна git-зависимость (см. [Использование крейтов в своем проекте](/docs/ru/crates/use-as-library/)). Примеров использования библиотеки пока нет: issue с примерами - <Status issue={287} />, а первый рабочий пример - [разбор SNBT](/docs/ru/crates/hello-nbt/).

| Что вы пишете | С чего начать | Состояние |
|---|---|---|
| Прокси | `mcrs_minecraft_protocol` и `mcrs_minecraft_network`. Оба в списке "без Bevy", и `xtask` проверяет, что они не линкуют игровые данные | Крейты есть. Сама библиотека прокси с маршрутизацией и пересылкой - <Status issue={296} />. Онлайн-режим - <Status issue={82} /> |
| Бот | Те же два крейта и `mcrs_minecraft_client_world`, который хранит состояние мира клиента без окна и рендерера. В списке "без Bevy" его нет | Состояние клиента отделено от рендеринга (<Status issue={301} />). Бот-ходок - <Status issue={302} /> |
| Карта или просмотрщик мира | `mcrs_minecraft_anvil` для регионов (он есть и в списке wasm32), `mcrs_minecraft_chunk` и `mcrs_minecraft_block` для данных, `mcrs_minecraft_mesh` для мешей | Крейты есть. Тайлы вида сверху без окна - <Status issue={297} />, просмотрщик моделей - <Status issue={298} /> |
| Инструмент для NBT, команд или датапаков | `mcrs_minecraft_nbt`, `mcrs_minecraft_snbt`, `mcrs_command`, `mcrs_minecraft_datapack` | Крейты есть. `mcrs_command` и `mcrs_minecraft_snbt` читают и пишут то же, что читает и пишет игра |
| Предпросмотр генерации мира | `mcrs_minecraft_worldgen_generator` и крейты `mcrs_minecraft_worldgen_*` | Предпросмотр по сиду через публичный API - <Status issue={299} />. Сам генератор совпадает с ванилью в parity-тестах на эталонных сидах |

"Крейты есть" значит, что они собираются в этом репозитории. Стабильный API или README при этом не обещаны: README есть только у шести крейтов.

## Зачем некоторым крейтам Bevy

Ниже слоя 4 Bevy - необязательная feature, а ниже слоя 2 необязателен и tokio. Начиная со слоя 4 Bevy обязателен: движок, ванильные плагины, клиент и сервер - это плагины Bevy. Если нужны только типы данных и кодеки, оставайтесь в слоях с 1 по 3 и собирайте с `--no-default-features`. Слои 4 и 5 разобраны в разделе [Слои](/docs/ru/concepts/layers/).
