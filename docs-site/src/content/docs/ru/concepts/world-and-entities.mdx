На этой странице показано, как mcrs раскладывает мир в памяти: блоки лежат в секциях и колонках, а мобы - это сущности ECS. Для блоков раскладка устоялась, а для сущностей и для API доступа к миру еще меняется. Если вы знаете Paper, отличий два. "Чанк" здесь означает две разные вещи, а моб не объект.

## Измерение состоит из колонок, колонка - из секций

| Уровень | Размер | Для чего нужен |
|---|---|---|
| Секция | 16 x 16 x 16 блоков | единица хранения блоков, света и сжатия палитры |
| Колонка | 16 x высота x 16 блоков | вертикальная стопка секций; владеет картами высот |
| Измерение | без границ | верхний контейнер; владеет индексом колонок и индексом секций |

mcrs говорит "секция" и "колонка" и избегает голого слова "чанк", потому что по нему не понять, какое из двух имеется в виду. Оба термина определены в [глоссарии](/docs/ru/reference/glossary/).

В движке каждый из трех уровней - сущность ECS с компонентом-маркером, который помечает ее вид. Маркеры `Section`, `Column` и `Dimension` лежат в `mcrs_minecraft_engine_world`. Координатные типы `BlockPos`, `SectionPos` и `ColumnPos` находятся в `mcrs_voxel`. Данные блоков внутри секции хранятся в палитре.

По умолчанию у каждого измерения одна ячейка со своим миром Bevy и тиком. При статическом делении на несколько ячеек у каждой свой мир, а локальный запрос видит только сущности этой ячейки. На этом строятся [Ячейки и путь к многим узлам](/docs/ru/concepts/scaling/) и плагины измерений, которые вы пишете по странице [Измерения - отдельные миры](/docs/ru/plugins/dimensions/).

## Билеты решают, что горячее

Билеты игроков держат колонки загруженными и задают покрытие симуляции. Билеты загрузки хранятся на колонках; покрытие симуляции и стадии секций - в коде `lifecycle/` модуля мира. Холодное пространство остается вне активной симуляции.

## Единым API для чтения мира становится volume

Блоки читают несколько путей кода: крейт чанков, генератор мира, движок освещения, построитель мешей и клиент. У каждого было свое представление, и на "секция не загружена" каждый отвечал по-своему. Теперь у них один API - крейт слоя 3 `mcrs_minecraft_volume`.[^486]

У volume есть границы. Про каждую секцию он сообщает, можно ли в нее писать, или она только для чтения, принадлежит другому владельцу, не загружена или лежит снаружи. При доступе ничего не загружается, а ошибки - это типы, по которым можно делать match.

Для блоков, биомов, высот, света и блок-сущностей есть отдельные трейты; для блоков и блок-сущностей предусмотрены формы с записью. Трейты обобщенные, поэтому динамической диспетчеризации на каждый блок нет. Основной путь идет по секциям и палитрам, а доступ по одному блоку - курсор поверх этого пути.

На него перешли представление измерения в движке, высоты и биомы, снапшоты и свет, построение мешей и клиентское хранилище. Сохраненный чанк Anvil не читается как volume, а шаблоны структур ставятся по-своему, блок за блоком в порядке шаблона.

## Мобы - это сущности ECS

Мобы, предметы и падающие блоки - сущности Bevy. Их движение хранится в компонентах `MotionState`, `MotionKind` и `MotionId` из `mcrs_minecraft_engine_entity_motion`. У моба есть еще атрибуты. Если для моба установлен поддерживаемый мозг, у него есть компонент ИИ `BrainState`; при выключенном ИИ или отсутствии мозга для этого типа компонента нет. Проход движения параллельно обновляет их компоненты по замороженной сетке тел. Порядок разобран на странице [Как тик работает параллельно](/docs/ru/concepts/parallel-tick/).

Игрок тоже сущность Bevy с меткой `Player` и компонентами, например `Transform`, `PlayerGameMode` и `Vitals`. Его движение обрабатывается отдельно. Таблица игроков для ИИ строится по этим компонентам, а `publish_player_tiles` читает их и выпускает события репликации. Строки сетки тел и таблицы ИИ - проекции для этих потребителей. Они не заменяют сущность и не хранят отдельную модель ее здоровья.

Системы плагина могут запрашивать компоненты мобов в мире измерения. У игроков и мобов общий `Vitals`; очередь урона применяет удары к обоим, как описано на странице [Чтение данных игрока](/docs/ru/plugins/players/#здоровье-урон-и-смерть). API библиотеки еще может меняться. Полный подсчет памяти на секцию и сущность пока не закончен.[^324]
