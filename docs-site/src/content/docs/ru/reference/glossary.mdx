Последняя колонка - подсказка для тех, кто знает Paper или Minestom. Совпадение редко бывает точным, поэтому настоящим определением считайте первую колонку каждой строки. Прочерк значит, что близкой идеи нет.

<Aside type="note" title="Термины внутри Rust-кода">
Часть слов из терминов масштабирования (шард, ячейка, тайл) - это слова из дизайна в `docs/cells.md` и `docs/replication.md`. Некоторые части этого дизайна еще не построены. Что реально работает, показывает страница [Статус](/docs/ru/start/status/).
</Aside>

## Rust и Bevy

| Термин | Значение | Ближайшее в Paper или Minestom |
|---|---|---|
| ECS, сущность (entity), компонент (component), система (system) | В Bevy сущность - это id, компонент - данные, которые хранятся на ней, а система - функция, которая запускается для каждой сущности с нужными данными. Объектов с методами нет. | Ничего близкого. `Entity` в Minestom - объект, а здесь то же самое разделено на данные и функции. |
| Bevy-плагин (plugin) | Единица, которая добавляет в приложение системы и данные. Сервер - это группа плагинов `MinecraftServerPlugins`, и части можно отключать через `disable`. | Плагин Paper, но он добавляет в приложение функции, а не слушает события. Ближе расширения (extensions) Minestom. |
| Крейт (crate) | Пакет Rust. Крейты здесь называются `mcrs_minecraft_<name>`. | Модуль Maven или Gradle. |
| Слои 1-7 (layer) | Протокол и данные, сеть, игровые данные, движок, ваниль, рендеринг, приложения. Слой должен зависеть только от слоев ниже (README, Layers). | - |
| Ядро (kernel) | Чистая Rust-логика одного домена (блоки, физика, ИИ, свет) без Bevy и без tokio. Хост передает ей вид на мир. | - |
| Драйвер (driver) | Код, который владеет шардами домена, делает в них шаги и доставляет сообщения между ними в стабильном порядке. | - |

## Дизайн мира и масштабирования

| Термин | Значение | Ближайшее в Paper или Minestom |
|---|---|---|
| Домен (domain) | Область симуляции: обновления блоков, редстоун, жидкости, сущности. | - |
| Шард (shard) | Логическая единица причинности и владения внутри домена. Не поток и не квадрат пространства. | - |
| Ячейка (cell) | Владелец трехмерной области горячего пространства и единица размещения. Менять чанки в своей области может только владелец. | Регион Folia, очень приблизительно. |
| Дерево ячеек (cell tree) | Октодерево над ключами чанков одного мира. Листья - это ячейки. | - |
| Мир движка (world) | Одно трехмерное пространство со своим деревом ячеек. Измерение Minecraft - это один world. | `World` в Bukkit, `Instance` в Minestom. |
| Горячее и холодное пространство (hot space, cold space) | Горячее пространство обновляется каждый тик, его удерживает тикет. Холодное пространство - это данные в слое данных, у которых нет владельца. | Загруженные и выгруженные чанки, очень приблизительно. |
| Тикет (ticket) | Запрос держать область горячей: зона симуляции игрока, спавн, загрузчик чанков, жемчуг Края. | Тикет чанка в Bukkit (`addPluginChunkTicket`). |
| Слой данных, хранилище (data layer, store) | Версионированные чанки холодного пространства и их хранение на диске (`mcrs_engine_store`). | `ChunkLoader` в Minestom, очень приблизительно. |
| Связь и размещение (link, placement) | Связь соединяет две части сообщениями. Размещение определяет, где работает дальний конец: в том же потоке (inline), в другом потоке или на другой машине. | - |
| Muxer, edge | Шлюз для клиентов. Держит соединения, решает, что получает каждый клиент, и кодирует байты один раз для всех подписчиков. Edge - это один процесс muxer. | Прокси вроде Velocity, но только та его часть, что держит соединения. |
| Координатор (coordinator) | Владелец глобального состояния и дерева ячеек. | - |
| Стадия и лестница (stage, ladder) | Шаг, который вне тика превращает данные чанка в следующий уровень, например генерация и свет. Лестница - цепочка стадий одной колонки (`Filled`, `Run`, `Merged`). | - |
| Тайл (tile) | Квадрат колонок. Единица интереса к сущностям и работы с ними. Каждым тайлом владеет одна ячейка. | - |
| Tile delta, tile stream | События сущностей одного тайла за тик, а также снапшот плюс дельты в порядке тиков. | Обновления трекера сущностей, очень приблизительно. |
| Tier | Скорость обновления: близкие subject обновляются в быстром tier, далекие в медленном. | Радиус активации сущностей в Paper, очень приблизительно. |
| Cap, budget | Наибольшее число subject, видимых одному клиенту, и наибольшее число байт в секунду, которое тратится на сущности. | - |
| Subject, viewer | Сущность, которую видят, и клиент, который ее видит ([`replication.md`](https://github.com/andreypfau/mcrs/blob/main/docs/replication.md)). | - |
| Секция и колонка (section, column) | Секция - это 16x16x16 блоков. Колонка - стопка секций. | `Chunk` в Minestom, который хранит `Section`. |
| Row | Серверная запись сущности в плотной колонке тайла. Мобы и предметы - это row, а не сущности Bevy. | - |
| Entity key, order key | Ключ сущности: id, UUID (он же order key), источник новых UUID, ее случайный поток, тайл. | - |
| Brain, goals, wait | Стадия ИИ мобов. Ядро будит только тех мобов, которых называет таймер или факт. Цели (goals) выбираются по тайлам, а ожидания (wait) заменяют проверки на каждом тике. | Цели мобов в Paper (`Mob`, `Goal`), очень приблизительно. |
| Volume | Один API для блоков, высот и биомов, который используют генерация мира, клиент и ядра. | `Block.Getter` в Minestom, очень приблизительно. |
| Collision table | Таблица форм и флагов состояния блоков для ядра физики. | - |

## Совпадение с ванилью и тесты

| Термин | Значение | Ближайшее в Paper или Minestom |
|---|---|---|
| Exact parity | Наблюдаемое поведение очень близко совпадает с ванилью: протокол, сохранения, движение игрока, генерация. | - |
| Semantic parity | Совпадают смысл и результат. Порядок внутри тика может отличаться: редстоун, жидкости, обновления блоков. | - |
| Intentional deviation | Записанное намеренное отличие от ванили ([`spec/README.md`](https://github.com/andreypfau/mcrs/blob/main/docs/spec/README.md)). | - |
| Spec rule id | Id правила в спецификации, например `CMD-TP-013`. На него ссылаются тесты и issue. | - |
| Provenance label | Происхождение правила спецификации, например `source_suggested`. См. [Спецификации](/docs/ru/reference/specs/). | - |
| Oracle, oracle dump | Дамп вывода реального запуска ванили (`tools/vanilla-oracle`). Rust-тесты сравнивают с ним свой вывод поэлементно. | - |
| Фикстура, capture, recapture (fixture) | Эталонный файл для тестов, команда, которая его снимает, и повторная съемка. `MCRS_BLESS=1` перезаписывает ожидаемый файл у некоторых тестов. | - |
| Corpus | Версия игровых данных, к которой привязаны фикстуры ([`captures.json`](https://github.com/andreypfau/mcrs/blob/main/tools/captures.json)), а также корпус тестов Molang. | - |

## Процесс

| Термин | Значение | Ближайшее в Paper или Minestom |
|---|---|---|
| Clean-room | Автор спецификации, которому разрешено видеть игровой код, записывает поведение. Реализатор, который читает только спецификации и игровые артефакты, пишет код. Названия из игрового кода в репозиторий не попадают ([`clean-room.md`](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md)). | - |
| Spec issue, plugin issue | Пара issue. Сначала идет спецификация в `docs/spec/`. Реализация следует за ней и ссылается на id правил. | - |
| Снапшот (snapshot) | Тестовая версия игры. mcrs следует за самой новой, сейчас это `26.4-snapshot-7`. | - |
| DataVersion | Версия формата данных сохранения. Если она не совпадает, мир не загрузится, потому что data fixers нет (<Status issue={388} state="declined" />). | Та же идея, что в Paper. |

## Игровые данные и рендеринг

| Термин | Значение | Ближайшее в Paper или Minestom |
|---|---|---|
| Реестр, датапак (registry, data pack) | Реестры (блоки, биомы, измерения) загружаются из датапака. Сервер загружает 147 реестров (PERF.md, Server start). | `Registry` в Bukkit, `DynamicRegistry` в Minestom. |
| Resource location, key | Имя вроде `minecraft:stone`. Живет на границах (датапак, протокол, команды). Внутри кода используются числовые id ([`resource-location.md`](https://github.com/andreypfau/mcrs/blob/main/docs/resource-location.md)). | `NamespacedKey`, `Key` в Minestom. |
| Molang | Язык выражений Bedrock для анимаций и условий. У компилятора `mcrs_molang` есть пакетный бэкенд и бэкенд WGSL. | - |
| Impostor | Далекий моб, нарисованный запеченным спрайтом. | - |
| Arena, group table, GPU cull, depth pyramid | Термины рендерера: арены памяти для квадов, моделей и граней; таблица групп секций; отсечение на GPU; пирамида глубины для двухпроходной окклюзии (PERF.md, DECISIONS.md). | - |
| Hot | Параметр замеров клиента, который не дает быстрым ядрам CPU уйти в простой (`MCRS_HOT`). Не то же самое, что hot space. | - |
