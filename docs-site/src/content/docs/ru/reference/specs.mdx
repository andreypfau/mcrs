Файлы в `docs/spec/` написаны для ИИ-агентов и для людей, которые пишут спецификации. Они следуют правилам ASD-STE100 Simplified Technical English, как сказано в `docs/spec/README.md`. Они намеренно точные и сухие. Эта страница - карта. Найдите по ней файл и читайте уже его.
</Aside>

Каждый файл в [docs/spec](https://github.com/andreypfau/mcrs/tree/main/docs/spec) описывает поведение одного домена: входы, выходы, порядок, тайминги и константы в виде данных. Спецификация никогда не описывает устройство игрового кода. Спецификации - единственный источник игрового поведения, который реализатор вправе читать, чтобы узнать правило ([Clean-room](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md)). В заголовках некоторых спецификаций версией игры все еще названа `26.4-snapshot-4`. Проект следует <code dir="auto">{fact('snapshot')}</code> (`assets/minecraft/version.json`).

## Как читать правило

У правила есть заголовок с id, раздел поведения и строка происхождения (provenance):

```text
Provenance: source_suggested. Kind: semantic. Confidence: medium. Experiment: ...
```

Происхождение говорит, откуда взято правило (`docs/spec/registry.md`, раздел 0.3).

| Метка | Значение |
|---|---|
| `black_box_confirmed` | Подтверждено артефактом, который произвела игра, с указанием пути. |
| `source_suggested_black_box_confirmed` | Взято из эталонного поведения и согласуется с указанным артефактом. |
| `source_suggested` | Взято из эталонного поведения, артефакта пока нет. Уверенность не выше средней, приложен эксперимент. |
| `documentation` | Публичное поведение, описанное в документации для игроков. |
| `design` | Выбор mcrs. Правило объясняет почему. |
| `unresolved` | Не решено. Собрано в разделе в конце файла. |

Kind говорит, насколько точным должно быть правило: `wire` (байты и id, которые декодирует клиент ванили), `client agreement` (сервер должен согласоваться с клиентом), `semantic` (смысл и результат, не внутренний порядок), `layout` (позиции и размеры GUI), `deviation` (дефект эталона, где правило описывает корректное поведение), `unspecified` (parity-тест не должен это сравнивать).

Раздел "Intentional deviations" файла фиксирует, где mcrs намеренно отличается от ванили: id правила, эталонное поведение, видит ли это клиент и что с этим делает тест.

В `registry.md` сказано, что ни один из его экспериментов не запускался. Относитесь к правилу `source_suggested` как к утверждению, за которым пока нет игрового артефакта.
