## Что нужно

- Rust через [rustup](https://rustup.rs). Версию выбирать не нужно: [`rust-toolchain.toml`](https://github.com/andreypfau/mcrs/blob/main/rust-toolchain.toml) закрепляет `nightly-2026-09-02`, и rustup скачает ее при первом вызове `cargo`. Он же добавит rustfmt, clippy и цели wasm32.
- IDE: RustRover или IntelliJ IDEA с плагином Rust. Корень репозитория открывайте как проект Cargo. Условия лицензии RustRover проверьте самостоятельно.
- Официальный клиентский jar снапшота. Скачивать его вручную не нужно: mcrs берет его из папки лаунчера или при первом запуске скачивает с Mojang в ту же папку и проверяет SHA-1.
- Для запуска mcrs Java не нужна. Часть инструментов (`tools/vanilla-oracle`, mob bench) требует Java 21 или новее.
- Операционная система: автор мерил и запускал все на macOS (Apple M4 Max, Metal). CI гоняет lint, clippy, проверки переносимости и тесты на Ubuntu 24.04, без крейтов, которым нужен GPU. Для Windows в коде есть путь к jar, но его никто не проверял.

Сколько длится первая сборка и сколько нужно места на диске, пока не измерено. В workspace 122 крейта, так что первая сборка будет долгой.

## Cargo для тех, кто знает Gradle

| Gradle | Cargo |
|---|---|
| `settings.gradle` с подпроектами | Корневой `Cargo.toml` с `[workspace]`. 122 участника лежат в `crates/` |
| `build.gradle` проекта | `Cargo.toml` крейта |
| `./gradlew run` | `cargo run`. Для mcrs добавляйте `--release`: отладочная сборка слишком медленная |
| `./gradlew build` | `cargo build` |
| `./gradlew test` | `cargo test`. В этом репозитории запускают `cargo nextest run` |
| Gradle wrapper закрепляет версию Gradle | `rust-toolchain.toml` закрепляет компилятор |
| Папка `build/` | Папка `target/` |
| Координаты Maven и версия | Имя крейта и версия либо git URL с `rev` |
| Lock-файл зависимостей | `Cargo.lock`, хранится в репозитории |
| Области `implementation` и `api` | `[dependencies]`; области `api` нет, видны все `pub`-элементы |

Крейты не опубликованы на crates.io (<Status issue={321} state="undecided" />). Поэтому собственный код сейчас живет в клоне репозитория или зависит от git-коммита.
