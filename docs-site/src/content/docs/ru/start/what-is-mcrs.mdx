## Что это

mcrs - это набор из 121 крейта на Rust для Minecraft Java Edition. Из них на Bevy ECS собраны сервер и клиент. В ECS (entity component system) мир хранится как данные в таблицах, а поведение описывают функции, которые называются системами. Если системы трогают разные данные, планировщик Bevy запускает их параллельно.

Проект следует за одним снапшотом игры за раз. Сейчас это 26.4-snapshot-7 (`assets/minecraft/version.json`). Совместимости со старыми версиями нет ([#412](https://github.com/andreypfau/mcrs/issues/412)).

Проект на раннем этапе (WIP). Репозиторий открыт с 2025-12-10.

## Что работает сегодня

- Генерация мира совпадает с настоящей игрой на эталонных дампах, элемент за элементом. Проверка идет на эталонных сидах и чанках, а не на любом сиде.
- Клиент рисует рельеф, небо, облака, свет и мобов. Все замеры сняты на одной машине, Apple M4 Max с macOS ([PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md)).
- Ванильный клиент того же снапшота может зайти на сервер в offline-режиме, писать в чат, менять режим игры и ломать блоки в креативе.

Полная таблица со ссылкой на каждый недостающий кусок есть на странице [Статус](/docs/ru/start/status/).

## Чего mcrs не делает

- Это не Paper. Bukkit-подобного API и фасада нет: решение [#437](https://github.com/andreypfau/mcrs/issues/437) их отклоняет, а публичный интерфейс - сами крейты и плагины. Загрузчика плагинов в виде jar, wasm или скриптов нет, и решения о нем пока нет. Сегодня свой код пишут как Rust-плагин для Bevy, который собирается вместе с сервером. Это ближе к Minestom, чем к Paper. См. [Это не Paper](/docs/ru/plugins/not-paper/).
- Это не продакшен. Сервер не сохраняет чанки ([#78](https://github.com/andreypfau/mcrs/issues/78)), не поддерживает online mode ([#82](https://github.com/andreypfau/mcrs/issues/82)) и слушает все сетевые интерфейсы без аутентификации.
- Это не лаунчер и не мод. Клиент это отдельное приложение на Rust. Текстуры и модели он читает из официального jar игры, а графики Mojang в репозитории нет.
