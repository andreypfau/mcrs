Здесь перечислены переменные `MCRS_*` и настройки клиента, а также параметры, которые меняют только замеры. Переменные сервера и тестов описаны на странице [Переменные окружения](/docs/ru/reference/env-vars/).

## Клиент

Нативный бинарник собирает переменные `MCRS_*` и отрезает префикс. Если имя встречается дважды, берется первое значение. Браузерная сборка читает поддерживаемые настройки из параметров запроса в нижнем регистре, например `?time=6000`, и игнорирует пустые значения. Нативные настройки файлов, окна и встроенного сервера не настраивают браузер. Точки входа лежат в `crates/mcrs_minecraft_client/src/native.rs` и `web.rs`.

Разбор зависит от настройки. Неверные значения проверяемых параметров, например `VIEW`, `OPTIONS` и `RESOLUTION`, останавливают нативный клиент с сообщением в stderr. Переключатели принимают `on`, `1`, `true`, `yes`, `off`, `0`, `false` и `no` в нижнем регистре; при неверном написании клиент пишет сообщение и оставляет значение по умолчанию. Числовые бюджеты `ASYNC`, `MESH`, `MESH_FLIGHT` и `UPLOAD` при ошибке разбора возвращаются к значениям по умолчанию. Неверный интервал `STATS` или `CENSUS` превращается в одну секунду.

У нативного клиента, собранного с `singleplayer`, есть встроенный сервер. Из [серверных настроек](/docs/ru/reference/env-vars/#сервер) он применяет `MCRS_WORLD_SEED`, `MCRS_WORLD_PRESET` и `MCRS_DEFAULT_GAMEMODE`; остальные серверные переменные эта точка входа не применяет. `MCRS_OPEN_TO_LAN` управляет адресом прослушивания, а порт выбирает операционная система.

| Переменная | По умолчанию | Что делает | Файл |
|---|---|---|---|
| `MCRS_SERVER` | нет | Нативный клиент: `host:port` сервера для подключения. Без переменной сборка singleplayer открывает титульный экран и поднимает собственный сервер для выбранного мира. Веб-клиент: `?server=` принимает HTTPS URL WebTransport вместе с `?cert=`; без обоих параметров браузер рисует только небо. | `native.rs`, `web.rs` |
| `MCRS_GAME_DIR` | папка данных платформы | Игровая папка: в ней лежат миры (в `saves`), `options.json`, `command_history.txt` и `ops.json` встроенного сервера. Без переменной клиент берет `~/Library/Application Support/mcrs` на macOS, `$XDG_DATA_HOME/mcrs` или `~/.local/share/mcrs` на Linux и `%APPDATA%\mcrs` на Windows. Без игровой папки нет автоматических путей для настроек и истории команд; явные пути по-прежнему можно задать через `MCRS_OPTIONS` и `MCRS_HISTORY`. | `game_directory.rs` |
| `MCRS_USERNAME` | `Player` | Имя игрока. | `config.rs` |
| `MCRS_VIEW` | `96` | Дальность прорисовки в колонках, от 2 до 96. Приоритетнее файла настроек. | `config.rs` |
| `MCRS_OPTIONS` | `options.json` в игровой папке | Путь к JSON-файлу с полями `fov`, `fov_effect_scale`, `smooth_light`, `clouds`, `brightness`, `view_distance`, `gui_scale`, `sensitivity`, `vsync`, `fullscreen`, `max_framerate`, `improved_transparency` и `operator_items_tab`. Неизвестные поля дают ошибку. Если переменная не задана, клиент читает `options.json` из игровой папки, когда такой файл есть. Настройки, измененные в меню, нативный клиент записывает обратно в файл. | `options.rs` |
| `MCRS_FULLSCREEN` | файл настроек (выкл) | Занять весь дисплей. Приоритетнее файла настроек. Не действует, если задана `MCRS_RESOLUTION`. | `config.rs` |
| `MCRS_OPEN_TO_LAN` | выкл | Встроенный сервер слушает на всех интерфейсах и объявляет себя. Аутентификации нет, поэтому любой в сети может зайти под любым именем. | `config.rs` |
| `MCRS_GUI_SCALE` | файл настроек (`0`, авто) | Фиксированный масштаб GUI. Приоритетнее файла настроек и меню. | `config.rs` |
| `MCRS_HISTORY` | `command_history.txt` в игровой папке | Файл, в котором хранится история команд. | `config.rs` |
| `MCRS_VSYNC` | файл настроек (выкл) | Вертикальная синхронизация. При запуске приоритетнее файла настроек. | `config.rs` |
| `MCRS_OCCLUSION` | вкл | Тест окклюзии по пирамиде глубины. `0` рисует каждую группу, которая проходит пирамиду видимости (frustum) и граф пещер. | `config.rs` |
| `MCRS_CAVE` | вкл | Отсечение по графу пещер. | `config.rs` |
| `MCRS_CHUNK_MAP`, `MCRS_LIGHT_LEVELS` | выкл | Отладочные оверлеи. | `config.rs` |
| `MCRS_ASYNC` | половина ядер, не меньше 4 | Максимум потоков нативного асинхронного вычислительного пула (построение мешей, декодирование колонок, освещение). Браузерная точка входа не применяет эту настройку. | `config.rs`, `native.rs` |
| `MCRS_MESH`, `MCRS_MESH_FLIGHT` | 2048, 2048 (web: 32, 128) | Сколько секций построитель мешей берет за кадр и сколько задач может быть в работе одновременно. | `config.rs` |
| `MCRS_UPLOAD` | `4` | Бюджет загрузки на кадр, в МиБ. | `config.rs` |
| `MCRS_ARENA` | 192,640,512 (web: 32,208,80) | Базовые бюджеты арен в десятичных МБ для квадов, моделей и граней, в виде `quads,models,faces`. Нативная точка входа умножает каждый бюджет на 4, браузер использует как есть. Буферы растут по мере надобности. | `config.rs`, `native.rs`, `web.rs` |
| `MCRS_CERT` | нет | Хеш сертификата для веб-клиента, который подключается к серверу. Только веб-сборка. | `config.rs` |

`operator_items_tab` по умолчанию равен `false`. Значение `true` в файле настроек разрешает вкладку предметов оператора, если у игрока есть права оператора. Кнопки для этого параметра в настройках управления пока нет.[^1033]

## Параметры для замеров

Не задавайте переменные из этого раздела для обычной игры. Они намеренно меняют то, что клиент рисует или измеряет.

| Переменная | По умолчанию | Что делает |
|---|---|---|
| `MCRS_HOT` | выкл | Только нативный клиент с `dev`. Держит одно ядро CPU занятым, чтобы частота не снижалась во время замеров. |
| `MCRS_GPU_HOT` | нет | Сжигает после кадра заданное число рабочих групп GPU, чтобы GPU оставался на полной частоте. |
| `MCRS_STATS` | нет | Секунды между строками F3, которые пишутся в лог при скрытом оверлее. |
| `MCRS_PROBE` | авто | `0` выключает временные метки проходов GPU; `1` запрашивает их каждый кадр. В автоматическом режиме они нужны для F3 или записи статистики в лог. Замеры энкодеров Metal выключают временные метки проходов. |
| `MCRS_RESOLUTION` | нет | Открывает окно размером ровно `<width>x<height>`. |
| `MCRS_LATENCY` | нет | Только нативный клиент с `dev`. Положительная подсказка о задержке кадров swapchain. |
| `MCRS_MONITOR` | самый быстрый дисплей с `dev`, основной без него | Только нативный клиент с `dev`. `primary` оставляет окно на основном дисплее; другие значения выбирают дисплей с наибольшей частотой обновления. |
| `MCRS_CENSUS` | нет | Только с `dev`. Секунды между строками, где подсчитаны трассированные колонки по стадиям. |
| `MCRS_TRACY_PREVIEW` | выкл | Нужны `dev` и `telemetry-tracy`. Отправляет изображения кадров в Tracy ценой одного считывания (readback) за кадр. |
| `MCRS_CHUNK_GUARD`, `MCRS_LIGHT_GUARD` | выкл | Только нативный клиент с `dev`. Проверка чанков следит за колонкой игрока; проверка света сравнивает небесный свет соседних ячеек воздуха в загруженных колонках с загруженными соседями. `warn` пишет ошибки в лог, `0` выключает проверку, любое другое значение вызывает панику при ошибке. |
| `MCRS_GPUTRACE` | нет | Только macOS с `dev`. Путь для записи трассы GPU. |
| `MCRS_RASTER` | нет | Только с `dev`. Доля больше 0 и не больше 1 для растрового прохода. Неверное значение пишет сообщение и игнорируется. |
| `MCRS_DRAWS` | все | Только с `dev`. Список номеров отрисовок через запятую, которые надо оставить; неверные элементы пишут сообщение и пропускаются. |
| `MCRS_SKY` | все | Только с `dev`. Список проходов неба через запятую, которые надо рисовать: `disc,twilight,celestial,stars,clouds`. |
| `MCRS_FLY`, `MCRS_TURN` | нет | Только нативный клиент с `dev`. Скриптовый полет: игрок летит вперед на спринте с этой скоростью полета (способность по умолчанию 0.05) и один раз разворачивается через `MCRS_TURN` секунд. |
| `MCRS_TIME` | нет | Фиксирует все часы на заданном числе тиков. |
| `MCRS_POS`, `MCRS_LOOK`, `MCRS_SCREEN`, `MCRS_CURSOR` | без переопределения; `SCREEN=title` | Настройки нативной съемки: стартовая позиция `x,y,z` в блоках, взгляд `yaw,pitch` в градусах, экран (`title`, `none`, `inventory`, `pause`, `options`, `video` или `accessibility`) и курсор `x,y` в единицах GUI. Браузер применяет только `LOOK`, и только когда рисует одно небо. |
| `MCRS_MENU` | нет | Только нативная сборка singleplayer с `dev`. После входа открывает контейнер с образцами предметов: `generic_9x1` по `generic_9x6`, `generic_3x3` или `hopper`. |
| `MCRS_PLAY` | выкл | Только нативная сборка singleplayer с `dev`. `1` запускает мир из папки, переданной аргументом, если он есть в списке `saves` игровой папки. |
| `MCRS_CAPTURE` | нет | Только нативный клиент. Записывает один скриншот в путь `.png`, когда сцена стабилизируется, и выходит. |
| `MCRS_SCREENSHOT_DIR` | `screenshots` | Папка нативных скриншотов; относительный путь отсчитывается от рабочего каталога. |
| `MCRS_SCENE_DIR`, `MCRS_SCENE_RECORD` | нет | Только нативный клиент с `scene`. Каталог для съемки сцены без окна и запись клиента ванили, из которой берутся сущности. |

Клиент читает их в `crates/mcrs_minecraft_client/src/config.rs`, `dev/knobs.rs` и `scene_capture.rs`. Нативная сборка по умолчанию включает `singleplayer` и `dev`.

## Настройка библиотеки

Приложение, которое встраивает клиент, настраивает плагины через публичные поля. У `ClientRegistriesPlugin` из `mcrs_minecraft_client_world::registries` есть поле `defer_definitions`. По умолчанию оно равно `false`: определения блоков загружаются синхронно. Нативная точка входа ставит `true`, чтобы окно могло открыться, пока определения загружаются в фоновой задаче; браузер оставляет синхронный вариант. Передача пакетов и загрузка ландшафта ждут определений. Это поле плагина, для него нет переменной окружения или ключа в файле настроек.[^1057]
