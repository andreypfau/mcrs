У mcrs есть собственный клиент, написанный на Rust с Bevy и wgpu. С ним можно летать по миру и смотреть на ландшафт, небо и мобов, но играть в выживание пока нельзя. Страница перечисляет, что работает, чего не хватает и чего это стоит.

<StatusRows areas="client" />

## Что умеет клиент

| Возможность | Состояние |
|---|---|
| Ландшафт с блочными моделями и светом игры | Работает, включая цветной свет блоков |
| Небо, облака и туман окружения | Работает |
| Мобы | Работает для пяти типов мобов, которые есть на сервере. Далекие мобы рисуются плоскими картинками (см. [Рендеринг](/docs/ru/client/rendering/)) |
| Оверлей F3 со временем кадра и стадий | Работает |
| Чат с подсказками команд | Работает |
| Ломание блоков в творческом режиме и блок, на который наведен прицел | Работает |
| Вход на сервер mcrs или на встроенный | Работает. Ванильный клиент того же снапшота тоже может зайти на сервер mcrs в офлайн-режиме |

| Частицы | <Status issue={137} state="wip" /> |
| Погода: дождь, снег, молнии | <Status issue={341} state="wip" />. Сегодня дождь только притемняет солнце и луну |
| Экраны инвентаря и контейнеров | <Status issue={521} state="wip" /> для инвентаря игрока, экраны - в <Status issue={129} state="wip" />, <Status issue={130} state="wip" /> и <Status issue={131} state="wip" />. Клиент рисует экран инвентаря только при запуске с `MCRS_SCREEN=inventory`, и играть с ним нельзя |

## Платформы

PERF.md измерен на одной машине: Apple M4 Max с macOS и Metal. Только эту платформу проверил автор. Linux и Windows не подтверждены. CI не запускает на Ubuntu крейты, которым нужен wgpu, поэтому зеленый CI о них там ничего не говорит.

## Дальность прорисовки: 96 колонок и ее цена

Обзор по умолчанию - 96 колонок, втрое больше максимума ванили (32). Одного числа мало, поэтому вот три, снятые в одном сценарии: M4 Max, macOS, окно 2560x1440, сохранение `two-relight` (38 025 колонок и 295 511 секций в памяти), статичный вид, с `MCRS_HOT=1`, чтобы ядра CPU держали частоту.

| Что | Значение | Где |
|---|---|---|
| Кадр движка на CPU | 1,12 мс медиана, 1,33 мс худшая секунда | [PERF.md, Hardening](https://github.com/andreypfau/mcrs/blob/main/PERF.md#hardening) |
| Кадр GPU | 3,7 мс с включенным тестом окклюзии, 6,0 мс с выключенным (`MCRS_OCCLUSION=0`). Заметка в PERF.md считает 3,7 мс выше своего потолка | PERF.md, Hardening |
| Память процесса | 12 ГБ | [PERF.md, Render distance](https://github.com/andreypfau/mcrs/blob/main/PERF.md#render-distance) |

Цифра 12 ГБ взята из раздела Render distance, который написан до работы над окклюзией, так что в новой сборке она может отличаться. Ограничение памяти на 96 колонках - <Status issue={337} state="wip" />. На 96 колонках кадр упирается в GPU, а не в CPU. Полет на максимальной скорости обходится дороже, чем стояние на месте: 1,56 мс медиана и 5,0 мс худшая секунда кадра движка в том же сценарии.

Если GPU или RAM меньше, чем в этом сценарии, можно уменьшить `MCRS_VIEW` (число колонок, которое запрашивает клиент). В таблице Render distance в PERF.md 12 колонок дают 0,71 мс времени движка (на более старой сборке). Чисел для других машин нет.

## Запуск

Бинарных загрузок нет, поэтому собирать нужно из исходников. Шаги короткие и живут в репозитории, а не здесь: см. [README, Quick start](https://github.com/andreypfau/mcrs#quick-start). Клиент принимает папку мира и запускает для нее собственный сервер. Текстуры и модели он читает из официального jar игры, потому что в репозитории нет графики Mojang.

<Aside type="caution" title="WIP">
Подробное руководство для игроков появится до альфы. До тех пор на этой странице нет шагов, которые не прогоняли на чистой машине.
</Aside>

Сервер и правила его миров описаны в разделе [Миры и сохранения](/docs/ru/server/worlds/). Все числа и методику см. в [PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md).
