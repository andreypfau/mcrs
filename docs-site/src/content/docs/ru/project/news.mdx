Это журнал изменений mcrs. В каждой записи сказано, что влито, что изменилось для тех, кто пишет плагины, и чего еще нет. Пометка "Breaking" стоит там, где старый код плагина перестает компилироваться. Новые записи сверху.

Последнему тегу 27 дней, и после него влито 152 PR, поэтому первая запись рассказывает о работе, у которой еще нет тега.

## После v0.5.8 (тега пока нет)

Запись охватывает период с 2026-10-14 по 2026-11-10. За это время 6 авторов сделали 874 коммита и влили 156 PR. 123 PR прислал andreypfau, еще 33 - пять других людей.

### Что влито

- Миры тикают параллельными ячейками за потоком-мультиплексором (muxer) и общим слоем данных (<Status pr={646} state="works" />).
- На сервере появились мобы с параллельной стадией ИИ, клиент рисует мобов, и есть бенчмарк на 50 000 свиней (<Status pr={651} state="works" />).
- Работают физика сущностей, проверки движения и симуляция блоков (<Status pr={648} state="works" />), а также очереди тиков блоков и событий блоков (<Status pr={477} state="works" />).
- Баны игроков и белый список работают по своим спецификациям (<Status pr={637} state="works" />, <Status pr={635} state="works" />).
- Перед остановкой сервер отключает и сохраняет каждого игрока (<Status pr={624} state="works" />).
- Игрок может ломать блоки в творческом режиме (<Status pr={643} state="works" />).
- Добавлен лендинг mc.rs с переключателем языка (<Status pr={629} state="works" />, <Status pr={633} state="works" />), а CI проверяет, что клиент компилируется под `wasm32` (<Status pr={622} state="works" />).
- Читатель VarInt и VarLong теперь отвергает биты вне диапазона (<Status pr={653} state="works" />).
- NBT читает и пишет две кодировки Bedrock, little-endian для хранения и varint для сети, рядом с кодировкой Java (<Status pr={679} state="works" />).
- Новый крейт `mcrs_minecraft_text_flatten` заполняет переводы в плоском тексте. Раньше переведенная причина отключения показывала пустую строку, а теперь показывает свой fallback или ключ (<Status pr={680} state="works" />).
- У ломания блоков в режиме выживания появилась спецификация, снятая с ванильного сервера (<Status pr={686} state="works" />). У установки блоков в творческом режиме тоже, и тоже с ванильного сервера (<Status pr={645} state="works" />, <Status pr={692} state="works" />).
- Подтверждение телепорта работает по спецификации. Пока клиент двигается, сервер повторно шлет неподтвержденный телепорт, а тесты проверяют это через скриптового клиента (<Status pr={683} state="works" />, часть <Status issue={623} />).
- CI гоняет собственные pull request проекта одной задачей на собственном раннере, а pull request из форков на машинах GitHub, и правка только в `docs/` ничего не собирает (<Status pr={691} state="works" />). Cargo один раз разрешает фичи для всего workspace (<Status pr={685} state="works" />).
- Для агентов, которые пишут код, появились `AGENTS.md`, скиллы и правила по путям (<Status pr={687} state="works" />). Как ими пользоваться, написано в разделе [Как внести вклад](/docs/ru/contributing/#работа-с-агентом).
- У лендинга появились метаданные для поисковиков, `robots.txt` и sitemap (<Status pr={684} state="works" />).

### Breaking для авторов плагинов

Плагин здесь - это код на Rust, который компилируется в сервер.

- `MinecraftServerPlugin` стал группой плагинов `MinecraftServerPlugins`, в которую входят, например, `ServerCorePlugin`, `DimensionWorldsPlugin`, `WorldGenPlugin` и `ServerNetworkPlugin`. Любой из них можно отключить или заменить (<Status pr={551} state="works" />). Затем плагины движка переехали в новый крейт `mcrs_minecraft_engine_server`, а `mcrs_minecraft_server` хранит группу для ванили (<Status pr={592} state="works" />).
- Ни один крейт библиотеки больше не читает окружение или рабочий каталог ради настроек. Операторы теперь задаются полем `ops` плагина, а настройки клиента - ресурсом `Knobs` (<Status pr={548} state="works" />). Подробности есть в [Переменных окружения](/docs/ru/reference/env-vars/).
- `Text::to_legacy_lossy` удален. Берите вместо него `plain_text` или `legacy_text` из `mcrs_minecraft_text_flatten`, которые принимают еще и `Language` (<Status pr={680} state="works" />).
- У методов чтения и записи в `mcrs_minecraft_nbt` больше нет суффикса `_be`, так что вместо `get_u8_be` теперь `get_u8` (<Status pr={679} state="works" />).

### Новое для авторов плагинов

- Плагин может добавлять плагины в мир каждого измерения через `add_dimension_plugin` или в мир одного измерения через `add_dimension_plugin_to` (<Status pr={552} state="works" />).
- Событие чата можно отменить. Наблюдатель может остановить строку или заменить ее текст до рассылки (<Status pr={636} state="works" />, часть <Status issue={283} />). События входа, выхода, движения и блоков не готовы.

### Чего еще нет

- Нет онлайн-режима (<Status issue={82} />).
- Нет загрузчика плагинов вне сборки сервера, и решения по нему тоже нет.
- Нет заявлений о скорости относительно другого сервера. Прогоны бенчмарка предварительные, об этом написано на странице [Производительность](/docs/ru/project/performance/).

## v0.5.8, 2026-10-14

Коммит `bf147fb2c`, два коммита после v0.5.7.

Версия workspace теперь 0.5.8, а CI запускает мутационное тестирование только по запросу. Для авторов плагинов ничего не ломается. Крейты по-прежнему не опубликованы (<Status issue={321} />).

## v0.5.7, 2026-10-13

Коммит `4fe86dc75`, два коммита после v0.5.6.

Проверка `xtask` теперь отвергает литерал, который называет любой каталог назначения фикстур. Второй коммит повышает версию. Для авторов плагинов ничего не ломается, потому что этот тег меняет только тестовый инструментарий. Не хватает того же, что в v0.5.8.

## v0.5.6, 2026-10-13

Коммит `e57c49ebe`, семь коммитов после v0.5.5.

Parity-тесты и фикстуры теперь загружают дампы оракула, золотые файлы протокола и золотые файлы данных через один загрузчик фикстур, который находит их по имени и проверяет версию. Появились две новые проверки `xtask`. Первая предупреждает о заявлениях про ваниль, которые проверяются литералами вне parity-файлов. Вторая проверяет, что parity-тесты сравнивают с фикстурами, загруженными по имени. Для авторов плагинов ничего не ломается. Не хватает того же, что в v0.5.8.
