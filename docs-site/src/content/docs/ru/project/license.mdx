Здесь написано, под какими лицензиями можно использовать mcrs, как проект связан с Mojang и какое правило не пускает код игры в репозиторий. Прочитайте страницу перед тем, как форкать проект, встраивать его в продукт или отправлять первый pull request.

## Лицензию выбираете вы: Apache 2.0 или MIT

mcrs распространяется под лицензией [Apache License 2.0](https://github.com/andreypfau/mcrs/blob/main/LICENSE-APACHE) или [MIT](https://github.com/andreypfau/mcrs/blob/main/LICENSE-MIT), на ваш выбор. В `Cargo.toml` workspace указано `license = "MIT OR Apache-2.0"`.

Код, адаптированный из [valence](https://github.com/valence-rs/valence), сохраняет собственное уведомление, [лицензию MIT авторов Valence](https://github.com/andreypfau/mcrs/blob/main/LICENSE-VALENCE-MIT).

## Связи с Mojang и Microsoft нет

mcrs не связан с Mojang или Microsoft. Minecraft - торговая марка Mojang Synergies AB.

## Материал Mojang берется из JAR игры, который есть у игрока

README сообщает, что в репозитории нет графики Mojang. Клиент читает текстуры и модели из официального JAR игры, который есть у игрока. Таблицы данных и отчеты в `assets/` заново генерируются из JAR игры одной командой, поэтому переход на новый снапшот в основном сводится к обновлению данных.

<Aside type="note" title="Это не юридическая консультация">
Страница повторяет то, что репозиторий говорит о себе. Юридического заключения она не дает. Если оно нужно, например для форка или хостинга сервера, обратитесь к юристу.
</Aside>

## Поведение пишут по спецификациям (clean-room)

mcrs берет поведение игры из письменных спецификаций и никогда из ее кода. Такой способ работы называют clean-room, и он делит работу между двумя людьми. Автор спецификации может читать игру и записывает только поведение. Реализатор читает только спецификации и артефакты, которые выдает игра, и никогда не читает декомпилированный или деобфусцированный код игры.

Имена из кода игры в репозиторий не попадают. Исключений шесть, это термины сообщества, которые перечислены в файле правил: `ResourceKey`, `TagKey`, `BlockPos`, `SectionPos`, `ColumnPos` и `PalettedContainer`.

Для контрибьютора из правила следует одно ограничение. Если вы читали код игры, чтобы разобраться в каком-то поведении, реализовать это поведение вы не можете. Полное правило лежит в [docs/clean-room.md](https://github.com/andreypfau/mcrs/blob/main/docs/clean-room.md), а что делать в таком случае, написано в разделе [Как внести вклад](/docs/ru/contributing/).
