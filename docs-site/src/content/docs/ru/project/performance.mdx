Каждая цифра на этой странице взята из [PERF.md](https://github.com/andreypfau/mcrs/blob/main/PERF.md), и рядом с каждой указаны машина и сценарий. Сравнений с ванилью, Paper или любым другим сервером здесь нет. Мы не публикуем их, пока бенчмарк из последнего раздела не прогонят на спокойной машине.

## Машина

Все замеры в `PERF.md` сделаны на одной машине: Apple M4 Max, 40 ядер GPU, macOS, Metal. Основной дисплей 3840x2160 на 60 Гц. Сборка release, nightly Rust, Bevy 0.19.1, wgpu 29. На Linux и Windows ничего не измеряли. Цифра отсюда говорит, что сделала эта машина, а не что сделает другая.

## Правила

- Цифра - это медиана установившихся строк прогона, а не один кадр и не среднее. Первые десять секунд после запуска отбрасываются.
- Разброс между двумя прогонами одного сценария - около 0,1 мс на полном кадре (wall frame) и от 0,05 до 0,2 мс на стадии. Изменение меньше этого - шум.
- Мы приводим время CPU движка, а не fps. На macOS полный кадр включает получение изображения свопчейна (swapchain acquire), которое ждет дисплей, поэтому пустая сцена показывает 3,5 мс полного кадра, из них 2,8 мс внутри acquire. Бюджет привязан к цифре движка (полный кадр минус acquire) и к временным меткам проходов GPU (`DECISIONS.md`, первая запись).
- Время движка читается с `MCRS_HOT=1`. Эта настройка держит одно ядро занятым, потому что производительные ядра снижают частоту, пока кадр спит. Без нее тот же пустой кадр дает медиану 1,37 мс и p99 4,0 мс, с ней 0,60 и 1,12. По умолчанию настройка выключена, и игрок при вертикальной синхронизации платит за разгон частоты. Обе цифры есть в `DECISIONS.md`.
- Каждое решение в `DECISIONS.md` - одна строка с цифрами, которые его обосновали.

Цель по времени CPU движка - 1,0 мс (`PERF.md`, Budget). `PERF.md` помечает замер выше потолка как "over the ceiling", и эта страница сохраняет такие строки.

## Клиент

Сценарий для этих строк: окно 2560x1440, `MCRS_HOT=1`, оверлей скрыт, сохранение `two-relight`, дальность прорисовки по умолчанию 96 колонок. Источник: `PERF.md`, раздел Hardening.

| Сценарий | Движок, медиана / p99 / максимум | Примечание |
|---|---|---|
| Пустой кадр (без сервера, только небо) | 0,80 / 0,94 / 0,94 мс | Нижняя граница движка. |
| 96 колонок, стоим на месте | 1,12 / 1,33 / 1,33 мс | В памяти 38 025 колонок и 295 511 секций. |
| 96 колонок, полет на максимальной скорости (`MCRS_FLY`), 120 с | 1,56 / 5,0 / 5,9 мс | Хвост p99 выше потолка. Два известных источника хвоста не исправлены. |

Что эти цифры скрывают:

- На 96 колонках кадр упирается в GPU, а не в CPU. Кадр GPU занимает 3,7 мс, выше цели в 1,0 мс. Процесс держит около 12 ГБ, а арены памяти заполнены на 50% из 4,3 ГБ (`PERF.md`, Render distance; этот замер сделан до прохода окклюзии, так что сегодняшняя память может отличаться).
- Вид на 96 колонок устанавливается около 80 с при бюджете загрузки 32 МБ (`MCRS_UPLOAD=32`). С умолчанием в 4 МБ он не устанавливается за четыре минуты.
- Установившийся вид показывает 0 КБ загрузки на кадр. В полете загружается от 300 до 450 КБ на кадр.

## Пока не измерено

- Память на загруженную секцию и на компонент сущности. README раньше это обещал, а в `PERF.md` такой таблицы нет. [#324](https://github.com/andreypfau/mcrs/issues/324) открыта и говорит, что число попадет в `PERF.md`, когда его посчитает тест.
- Стоимость тика простаивающего сервера и счет тиков с превышением времени. [#320](https://github.com/andreypfau/mcrs/issues/320) открыта. Сегодня цикл сервера после превышения сразу начинает следующий тик, без счета и без предупреждения.
- Время тика сервера под нагрузкой от игроков. Нагрузка ботами есть (`crates/mcrs_minecraft_server/examples/tick_load.rs`), но ее машина и условия не записаны, поэтому мы ее не приводим.
- Что-либо на Linux или Windows.

## mob-bench: метод без результатов

`benchmarks/mob-bench` загружает в один сервер 50 000 свиней и измеряет его тик, использование CPU и движение свиней. Тестовая обвязка лежит в `tools/mob-bench`. Он прогоняет mcrs, сервер ванили того же снапшота и еще один Rust-сервер через одни и те же фазы: простой, блуждание, скопление, стимул (паника после ударов по части свиней) и стоимость ИИ, каждую с подключенным клиентом и без него.

Автор помечает первую сессию как предварительную: все окна были под конкуренцией, потому что на машине одновременно шли другие сборки (load average до 84). README говорит, что для официальных прогонов нужна спокойная машина. Поэтому результата на этой странице нет.

Полная матрица занимает около 2,5 часов на M4 Max. Чтобы запустить:

```sh
cargo build --release -p mcrs_mob_bench -p mcrs --bins
MINECRAFT_EULA=true tools/mob-bench/run.sh
```

Другому серверу нужны свой чекаут и файлы, они описаны в README бенчмарка.

## Как повторить замер клиента

```sh
MCRS_STATS=5 ./target/release/mcrs_minecraft_client "<world folder>"
```

Команда пишет строку F3 в лог каждые пять секунд при скрытом оверлее. Настройки, которые задают сценарий (`MCRS_RESOLUTION`, `MCRS_SERVER`, `MCRS_FLY`, `MCRS_HOT`), описаны в [Переменных окружения](/docs/ru/reference/env-vars/). Для обычной игры они не нужны. Для захватов Tracy нужна фича `telemetry-tracy`.
